# Token 商业模型（TOKEN_SYSTEM）v1.0

> 状态：**已定案**（2026-08-08，基于 DeepSeek 官方 2026-08 定价）
> 定位：账号体系的经济核心——"上游 token 是成本，玩家点数是商品，双轨隔离，涨价不惊"。

| 模型 | 输入（缓存命中） | 输入（缓存未命中） | 输出 |
|---|---|---|---|
| V4-Flash | ¥0.02 / M | **¥1 / M** | **¥2 / M** |

2. ⚠️ **峰谷计费已实施**：高峰时段（9:00-12:00、14:00-18:00 北京时间）价格为平日 **2 倍**——用"缓存命中 + 本地优先"对冲。

## 2. 双轨设计与换算

| 轨 | 单位 | 性质 |
|---|---|---|
| 上游 token | LLM 计费单位 | **成本侧**：服务端实际消耗，按 DeepSeek 价结算 |
| 玩家点数 | 售卖单位 | **收入侧**：玩家充值/买断赠送的抽象货币 |

**换算基准**：1 点数 = 1 次"标准云端对话"（约 3.5k 混合 token：输入 3k + 输出 0.5k）。

单次对话成本测算（Flash，非高峰，缓存未命中）：
```
输入 3k × ¥1/M = ¥0.0030
输出 0.5k × ¥2/M = ¥0.0010
─────────────────────────
合计 ≈ ¥0.004 / 次
```
> 缓存命中时输入成本降 50 倍（¥0.00006），Persona/记忆不变时可大量命中——**收益巨大**。

## 3. 定价策略（安全垫 = 12.5 倍毛利）

| 项目 | 定价 | 说明 |
|---|---|---|
| **买断版** | $14.99（Steam） | **赠送 2,000 点数**（≈2,000 次云端对话，普通玩家 3-6 个月量；本地模型用户可用更久） |
| 点数包 小 | ¥6 / 500 点 | 重度玩家补充装 |
| 点数包 中 | ¥25 / 2,000 点 | 主力装（≈买断赠送量） |
| 点数包 大 | ¥68 / 6,000 点 | 云端依赖型玩家 |
| 免费 Demo | 100 点（一次性） | 体验核心对话，促转化 |
| 本地模型（Ollama） | **0 成本，不扣点数** | 主力玩家群体，几乎不产生成本 |

**毛利验证**：1 点售价 ¥0.0125（500 点 ¥6）vs 成本 ¥0.004 → 毛利 68%；即使 API 涨价 3 倍（¥0.012）仍基本打平上游、靠本地模型摊薄；若按中包 2,000 点 ¥25（¥0.0125/点）同样成立。**买断送 2,000 点相当于一次性的 ¥25 成本上限（全部云端极端场景），实际因本地模型兜底远低于此。**

## 4. 额度与降级链（游戏永远可玩）

```
玩家发起对话 → 服务端校验点数余额
  ├─ 余额充足 → 云端（Flash）→ metering 计量 → 扣点
  ├─ 余额不足 / 未联网 → 降级本地模型（Ollama，0 成本，不扣点）
  └─ 本地也不可用 → 降级模板对话（游戏继续，玩家知道"船员没精打采"）
```
- 买断玩家额度用尽不"断玩"，只是 AI 对话变少——买断是游戏，点数是增值 AI 服务；
- 限流：每账号 RPM ≤ 20、TPM ≤ 100k、并发 ≤ 1（防刷）；
- 免费 Demo 玩家：仅本地 + 模板（不开放云端，防滥用）。

## 5. 数据库定稿（对应 docs/ARCHITECTURE.md 4.5）

```sql
wallets         (user_id PK, points_balance BIGINT, version INT)          -- 乐观锁防并发扣点
transactions    (id, user_id, type[grant|purchase|consume|refund], points, ref_id, created_at)
usage_records   (id, user_id, model, prompt_tokens, completion_tokens, cache_hit BOOL, latency_ms, points_deducted, created_at)
quotas          (tier, rpm_limit, tpm_limit, daily_points, monthly_points)
```

## 6. API 定稿（对应 contracts/openapi/v1.yaml）

| 接口 | 返回/行为 |
|---|---|
| `GET /wallet` | `{ points_balance, tier, monthly_usage_tokens }` |
| `POST /billing/orders {plan}` | 创建订单 → 支付渠道（Steam 钱包 webhook / 微信 / 支付宝）→ 支付回调后 `grant` 入账 |
| `POST /agent/chat` | 正常：流式 AgentReply；`402` 余额不足（客户端降级本地/模板）；`429` 限流 |
| `POST /billing/activate {code}` | 兑换码（运营/赠礼用，后置） |

## 7. 成本上限测算（服务器侧预算）

| 场景 | 月成本估算 |
|---|---|
| 本地模型为主玩家（80% 用户） | 每玩家 < ¥1/月（云端仅 20% 对话） |
| 云端依赖玩家（20% 用户） | 每玩家 ~¥3-6/月（100 航程 × 10-15 次云端对话） |
| 1,000 活跃玩家（EA 期上限） | **< ¥2,000/月**（VPS $20-50 + API 混合，可控） |

> 结论：AI 成本不会成为 EA 阶段的亏损源；点数体系同时是收入来源与成本刹车。
