| 标记 | 含义 |

## 1. 产品定义

### 1.1 一句话

1675 年加勒比海开放世界航海沙盒 RPG：玩家从一艘小船和少量船员起步，通过航海、贸易、探索、社会关系、生态资源和岛屿经营，建立自己的船队、资产与势力。

### 1.2 产品形态

| 项目 | 决策 |
|---|---|
| 类型 | 单人第三人称航海沙盒 RPG + 船员 Agent 社会模拟 |
| 平台 | PC / Steam；手柄和无障碍输入保留接口 |
| 视角 | 岸上第三人称、甲板自由行走、舰桥指挥、海图规划 |
| 时代 | 1675 年加勒比；英、西、法、荷、葡、丹麦及地方社群并存 |
| 现实主义 | 无魔法、无海怪；传闻必须能还原为自然、人为或信息差 |
| 核心卖点 | 船员会记住玩家的选择，并通过关系、岗位、忠诚和背叛改变航程 |
| 存档 | 单机本地权威；全世界状态可保存、恢复和迁移 |
| 多人 | 不进入首个完整单机版本；保留边界，不以多人改变单机数据模型 |

### 1.3 不做什么

- 不把自由身份、族群和受压迫的人当成商品或轻松的赚钱系统；
- 不用 LLM 裁决金钱、伤害、价格、掉落、声望、天气和任务结果；
- 不做依赖猜谜才能继续的宝藏谜题；难点是信息、装备、路线和风险；
- 不把战斗做成唯一成长手段；商人、探险家、渔民、社群经营者和船员管理者都必须能成长；
- 不在首个完整版本承诺完整深海潜水、超复杂船舱物理、多人或全语音。

## 2. 体验目标

玩家应该持续感受到三件事：

1. **海是活的**：风、潮汐、海流、天气、鱼群、鸟群、植被和港口生产互相影响。
2. **人是真的**：船员有记忆、特质、文化、信仰、关系、利益和底线。
3. **选择有代价**：每次出航、交易、雇佣、战斗、采集和投资都改变后续世界。

## 3. 玩家进程与核心循环

### 3.1 单次航程循环

```text
港口整备 → 观察市场/天气/传闻 → 选择航线和任务
→ 分配船员岗位 → 航行、捕鱼或观测 → 遭遇天气/海盗/巡逻/生态事件
→ 锚泊或登陆 → 采集、交易、探索、谈判或战斗
→ 返回港口 → 卖货、发工资、维护、投资、处理关系
→ 航海日志记录事实 → 世界状态进入下一航程
```

### 3.2 长线循环

```text
小船与少量船员
→ 可靠航线和稳定收入
→ 更好的船、岗位、工具和信用
→ 资产、商路、社群关系和势力许可
→ 岛屿经营、船队运营和区域影响力
→ 玩家自己的航线与世界遗产
```

### 3.3 玩家路线

| 路线 | 核心收入 | 核心风险 | 关键成长 |
|---|---|---|---|
| 商人 | 贸易、仓储、金融、护航 | 价格、债务、封锁、海盗 | 信用、资产、船队 |
| 探险家 | 制图、生态观察、遗迹和自然资源 | 迷航、疾病、环境危险 | 图鉴、地图、装备 |
| 寻宝人 | 线索、沉船、遗迹、宝藏 | 错误信息、竞争、法律 | 线索网络、特殊装备 |
| 渔民/海上采集者 | 钓鱼、贝类、海草、活鱼舱 | 天气、资源枯竭、船体风险 | 渔具、冷藏/腌制、海域知识 |
| 私掠/海盗 | 护航、截获、战利品、悬赏 | 法律、通缉、外交和船员道德 | 舰炮、情报、势力许可 |
| 岛屿经营者 | 农业、渔场、工坊、港口服务 | 人口、维护、战争、生态压力 | 土地、建筑、政策和自治 |
| 船员社会管理者 | 训练、调解、关系和高效轮班 | 叛变、疾病、派系和离队 | 信任、岗位、个人任务 |

## 5. 系统需求

### REQ-SHIP 船舶

- 20 种船体目标；每种拥有船型定位、历史依据、尺寸、吃水、甲板、舱室、碰撞体、操控参数和存档 ID；
- 80 个改装模块目标；覆盖帆、桅杆、船体、炮位、货舱、医务、厨房、住所、瞭望、淡水和渔业功能；
- 60 个船上功能点目标；舵轮、锚机、缆桩、炮位、泵、货梯、货舱、厨房、活鱼舱和工具台必须可读、可交互或可由岗位使用；
- 船体分区损伤、进水、失火、倾斜、断帆、舵损、锚泊、走锚、靠泊和维修都有状态和恢复路径；
- 船的重量、吃水、帆面积、人员、载货和改装必须共同影响航行结果。

### REQ-CREW 角色与 Agent

- 玩家、核心船员、重要 NPC、普通 NPC、历史背景角色使用不同模拟等级；
- 船员具备技能、身体状态、特质、文化、宗教、法律身份、记忆、关系和职业目标；
- 好感、信任、忠诚、恐惧、士气、债务和声誉分别有含义，不允许用单一“好感”替代全部关系；
- Agent 只能提出对白、意图和建议；所有结果必须通过 Schema 和强逻辑系统；
- 船员能出现合作、争执、恋爱、嫉妒、罢工、偷窃、离队和叛变前兆，但每种结果都必须可追溯。

### REQ-WORLD 世界与生态

- 50 座岛屿目标；每座拥有自然档案、地质、山地/坡地、淡水、洞穴、海岸、暗礁、生境、资源和社会结构；
- 1,000—2,000 个植被内容条目目标，300 个动物条目目标；
- 天气、潮汐、海流、能见度、水温、浑浊度、植被状态和动物行为必须互相影响；
- 动物使用确定性行为层，不使用 LLM；鱼群、鲸豚、海龟、鲨鱼、鸟类、昆虫和陆生动物都有生境与行为标签；
- 生态资源拥有恢复、枯竭、保护、过度采集和污染后果。

### REQ-SOCIAL 社会与势力

- 英、西、法、荷、葡、丹麦殖民网络、原住民社群、自由社群、马龙社群、商会、宗教团体、海盗和走私网络必须有不同制度与关系；
- 战争、停战、封锁、私掠证、检查、通缉、护航、港口准入和外交后果必须可保存；
- 宗教影响节期、饮食、建筑、葬礼、信任和冲突，不简单映射善恶；
- 奴役和强迫劳动作为历史社会制度与冲突背景处理，不设计为可轻松套利的商品系统。

### REQ-ECONOMY 经济与资产

- 商品、鱼获、农产品、动物相关合法服务、建筑服务、船坞、工资、保险和债务都进入统一经济系统；
- 岛屿、房屋、工坊、仓库、农地、渔场、船坞和商铺具备所有者、估值、维护、收入、税费和法律状态；
- 经济必须解释钱从哪里来、为什么值钱、谁承担风险、失败后如何补救；
- 任务奖励和 Agent 输出不能绕过经济系统凭空发钱。

### REQ-PLAY 玩家表达与小游戏

- 玩家可选择性别表达、姓名、称谓、发型、肤色、体型范围、服装、饰品和职业装备；
- 服装必须同时服务外观、气候、职业、文化和法律身份，不强制把所有装扮变成战斗数值；
- 扑克牌和塔罗牌是社交/信息/风险玩法，不允许无限刷钱；
- 特殊奖励和武器必须拥有来源、代价、强度边界、维修和丢失处理；
- 玩法失败必须留下债务、关系、伤病、声誉或资源后果，而不是简单读取检查点。

## 7. 历史与敏感内容规则

- 所有历史制度、势力、社群、宗教和商品链都要标注“史实锚点 / 游戏化推断 / 虚构内容”；
- 1675 年允许出现殖民、私掠、奴役、强迫劳动、宗教冲突和疾病，但表现必须给受影响者主体性，并提供内容警告与跳过选项；
- 捕鲸、珍稀动物交易、赌场牌局、土地占有和殖民经营必须在设计中写出社会后果，不做无代价的资源按钮；
- 塔罗牌可作为牌面、信仰、心理和信息系统，不引入真实超自然能力；
- 不使用现代国家、现代银行、现代职业称谓和现代价值体系直接替代 1675 年语境。

## 8. 技术与数据要求

- 跨端数据必须先落入 `contracts/`，客户端、服务端和官网同步；
- `game/Assets/Scripts/Systems/` 只做确定性裁决，不放 LLM、HttpClient 或网络代码；
- 每份状态只有一个系统能写入；事件、任务、UI、Agent 只能读取或提出建议；
- `game/AgentCore/` 零 Unity 依赖、零第三方依赖；
- 存档必须包含版本号、世界时间、玩家、船、船员、关系、资产、经济、生态、任务和日志；
- 所有内容条目必须有唯一 ID、来源、授权、阶段、所有权、依赖、测试 ID 和回退策略。

## 10. 需求完成定义

需求文档只有在以下条件全部满足时才算完善：

- 每个玩法都有独立设计入口；
- 每个玩法都写清玩家循环、资源、时间、风险、奖励、失败、关系和经济后果；
- 每个玩法都有数据实体、唯一写者、跨系统事件和存档字段；
- 每个玩法都有首个垂直切片和批量内容阶段；
- 设计目标与 D7 已有代码边界不冲突；
