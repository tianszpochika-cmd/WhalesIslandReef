# 创意入口（IDEA INTAKE）

> 这里不是需求文档，也不是开发清单。它只接收新想法，经过筛选后才能进入 `REQUIREMENTS.md` 和 `design/gameplay/`。

## 1. 新想法登记格式

```text
idea_id:
name:
player_value:
related_requirements:
related_gameplay:
historical_or_fictional:
systems_affected:
unique_writer:
failure_and_recovery:
content_cost:
risks:
decision: intake | designed | rejected | post_launch
```

## 2. 准入检查

- 是否服务“海是活的、人是真的、选择有代价”；
- 是否有可重复的玩家循环，而不是一次性噱头；
- 是否能在 1675 年语境下解释；
- 是否有唯一写者和失败恢复；
- 是否会与现有玩法、性能、历史或敏感内容冲突；
- 是否有最小垂直切片和批量扩展边界。

## 3. 当前已吸收的玩法

用户此前提出的岛屿经营、捕鲸、钓鱼、活鱼舱、珍稀动物、猫狗、扑克牌、塔罗牌、好感/爱情、资产买卖、金融、种植、服装、副业、性别表达、特殊奖励、特殊武器、探索寻宝、部落交易、水果和蔬菜，已经进入：

- `REQUIREMENTS.md` 的 GP-01—GP-22；
- `design/gameplay/` 的对应专题；
- `DEV_ROADMAP.md` 的 D9—D16 工作包。

新想法不得再在本文件复制一份“第二需求表”。
