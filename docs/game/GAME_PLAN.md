# 大陆个人开发者 · Steam 上架合规分析 + 3D 航海 Agent 游戏开发计划

> 项目定位：纯 Agent（AI 船员）驱动的 3D 航海冒险游戏，单人多开模式，买断制上架 Steam。
> 编写日期：2026-08-07 ｜ 适用主体：中国大陆个人开发者（无公司）
> 设计原则：**强逻辑**（玩家可理解、可预测、可博弈的确定性系统）× **重交互**（与 AI Agent 的高频、有后果的互动）

---

## 0. 结论先行（TL;DR）

1. **个人可以上架 Steam，不需要注册公司，也不需要国内游戏版号**（面向海外发行路径）。Steam Direct 是人人可用的自出版通道。
2. 硬成本：每款游戏 **$100 注册费**（累计净收入 $1,000 后自动返还）+ Valve **30% 分成**（收入越高比例越低，最高档 20%）。
3. 税务：填写 **W-8BEN**（勾选中美税收协定）后，美国地区销售预扣税率由 30% 降至 **10%**（部分版权类收入实践中可更低）；**3 年有效需续签**。
4. 收款：国内个人普通银行账户直收美元不便，主流方案是 **Payoneer（派安盈）** 虚拟账户，Steam 每月结算（余额 ≥ $100 才打款）。
5. 时间约束：缴费后 **30 天冷却期**（不可跳过）+ 商店页"即将推出"公开 **≥2 周** + 审核 **1–5 个工作日** → 从注册到可上线最快约 5–6 周，建议预留 3–4 个月做愿望单积累。
6. 游戏方案：Unity 6 / UE5 做 3D 海洋与航行，**本地小模型（Ollama + Qwen 系）+ 云端大模型（DeepSeek 等）混合架构**驱动 AI 船员，三层记忆系统 + 结构化 JSON 输出，保证"像人一样记得住、说得对、有后果"。
7. 盈利判断：买断制 $14.99–$19.99，单人 + 资产商店成本可控，核心风险不在上架合规，而在**内容量与 AI 表现力**。

## Part A · 大陆个人上架 Steam 的规则与条件

### A.1 主体资格：个人即可，无需公司

- Steamworks 开发者身份支持 **"个人/独资经营者"** 注册，与公司享有同等上架权利。
- 填写要求（个人开发者）：
  - 法定全名用**拼音**，必须与身份证、收款银行卡姓名完全一致（不能用昵称/英文名）；
  - 地址、邮箱、电话用英文或拼音填写，精确到门牌号；
  - 上传身份证正反面照片，部分账号需补充**手持身份证照片**核验（KYC）；
  - 主体类型切勿错选公司/合伙企业，否则进入公司资质流程（需 DUNS 号等，慢 2–4 周）。
- 年龄/民事行为能力：需为成年人、具备完全民事行为能力，可独立签署《Steam Distribution Agreement》（Steam 数字发行协议，纯线上电子签署）。

### A.2 费用结构

| 项目 | 金额 | 说明 |
|---|---|---|
| Steam Direct 注册费 | **$100 / 款** | 每款游戏一次，微信/支付宝可付（按实时汇率）；**不可用钱包余额**；不退款 |
| 费用返还 | 累计调整后总收入 ≥ **$1,000** 时自动返还 $100 | 含游戏本体 + 内购收入 |
| Valve 分成 | 首 $1,000 万 **70%** 归开发者 | $1,000 万–$5,000 万区间 75%；$5,000 万以上 80% |
| 其他 | 无月费、无年费、无最低销量要求 | 免费拿个 demo 发布也需要单独 $100（若作为独立 app 发布） |

### A.3 税务：W-8BEN 是省税关键（必读）

- 中国大陆个人 = **非美国税务居民**。税务问卷勾选"个人" + "适用中美税收协定"。
- 系统自动生成 **W-8BEN 表**；其中"中国纳税人识别号（TIN）"直接填**身份证号**即可（我国身份证号即个人法定纳税人识别号）。
- 效果：不填 → 美国 IRS 预扣 **30%**；正确填写 → 按协定降至 **10%**（版权/特许权类收入，实践中部分情形可更低甚至 0%，以 Steam 税务核定为准）。
- 三个致命坑：
  1. **Foreign TIN 缺失** → 视为无协定资格，默认扣 30%；
  2. **3 年有效期** → 过期未更新，Steam 自动恢复 30% 预扣，到手金额会突然暴跌；
  3. **地址一致性** → W-8BEN 地址须与收款账户地址逻辑一致，否则人工审核判无效。
- **国内义务**：Steam 扣的是美国税，你还需要按中国税法**自行申报个人所得税**（通常按经营所得/劳务报酬处理，税率阶梯约 5%–35%），建议每年留存 Steamworks 财务报表（Gross Revenue / Withholding Tax CSV）+ 银行流水做证据链。年净收入很低时个税负担可忽略，但**不申报有合规风险**。

### A.4 收款：Payoneer 是主流方案

- Steam 每月结算一次（余额 ≥ $100 才发起），结算币种默认 USD。
- 国内普通个人银行卡直收美元受限，主流做法：**Payoneer（派安盈）** 或 PingPong 提供虚拟美国银行账户（含 SWIFT/BIC），绑定到 Steamworks 财务设置。
  - 到账时效约 3–5 天，手续费约 1.5%–2%；
  - 账户持有人姓名必须与身份信息**完全一致**，否则核验失败、放款延迟 ≥14 天；
  - 备选：银行电汇（单笔 $35–50 手续费，适合 ≥$5,000 的大额结算；需 SWIFT/IBAN 与开户行完整英文信息）。
- 切勿频繁更换收款账户，会触发重新审核（7–14 天）。

### A.5 版号边界：海外发行不需要版号

- 国内《网络出版服务许可证》/游戏版号，针对的是**在中国境内从事网络游戏出版运营**的行为（国内平台发行，如 WeGame、蒸汽平台、国内手机渠道）。
- 通过 **Steam 国际版**面向全球发行（含国区用户可正常购买），属于海外渠道发行，**不强制要求国内版号**——这是当前大量中国独立开发者的标准路径（近年国产独立游戏在 Steam 上架普遍走此通道）。
- 需要自行评估的现实边界：
  - 游戏内容若涉敏感题材（历史、政治、血腥、赌博机制等），有被国内举报/监管关注的风险，建议内容主动做温和化处理；
  - 若未来想进国内平台，再另行申请版号（周期长、成本高，通常由发行商操办）；
  - 本文档假设：游戏面向全球英文+中文市场发行，内容合规自查严格。

### A.6 上线时间线（硬约束）

```
注册签约 → 缴费 $100 → KYC+税务+收款信息审核(1–3 个工作日)
   → 30 天冷却期(不可缩短) → 商店页"即将推出"公开 ≥2 周(可并行于冷却期后)
   → 提交审核(1–5 个工作日) → 正式发售
```
- 最短路径约 **5–6 周**；行业建议预留 **3–4 个月**：先上"即将推出"页攒愿望单，愿望单数量是 Steam 算法推荐的核心信号。
- 商店页必备资产：主图 616×353、页眉图 460×215、**≥5 张实机截图（建议 8–10 张）**、60–90 秒实机预告片、短描述（≤300 字符）+ 长描述（支持 HTML）、精准标签。

### A.7 内容合规自查清单（上架前必过）

- 素材授权：背景音乐、美术、字体、模型、IP 形象——**全部要有可商用授权**，勿用无授权网络素材（Steam 对版权侵权零容忍，直接下架并牵连账号）；
- 无恶意代码 / 无作弊功能 / 无隐私窃取；
- 无仇恨言论、色情裸露、未经授权的真实人物、NFT/区块链代币、广告为主商业模式；
- 完成年龄分级问卷（免费，自动适配 ESRB/PEGI/各国分级）；
- 首次发行账号有"首几款游戏"审慎期，游戏质量与商店页配置会显著影响首轮曝光与评价。

### A.8 财务模型（盈亏平衡参考）

| 场景 | 定价 | Steam 抽成后到手/份 | 需售出（覆盖 $100 费 + $500 资产/工具） |
|---|---|---|---|
| 保守 | $14.99 | ≈ $10.5（税后约 $9.5） | ≈ 65 份 |
| 基准 | $19.99 | ≈ $14（税后约 $12.6） | ≈ 50 份 |

> 独立航海题材 Steam 上参考区间：中腰部作品销量数千到数万份。**盈亏平衡门槛极低**，真正的目标是内容口碑 + 愿望单转化。

## Part B · 2026 年主流技术方案

### B.1 引擎选型对比

| 维度 | Unity 6（推荐 ★） | Unreal Engine 5 |
|---|---|---|
| 海洋方案 | **Crest Ocean**（最主流海洋插件，FFT 波浪+浮力）；VR Ocean（Burst/Jobs，性能好） | 原生 **Water 插件**（GPU heightfield）+ **Buoyancy 组件**（浮筒 Pontoons）；第三方 Oceanology / Marine Buoyancy |
| 船只物理 | Crest 内置 buoyancy / 第三方浮力插件 | 原生 UBuoyancyComponent + Marine Buoyancy（自动生成浮筒参数） |
| Agent 集成 | C# + UnityWebRequest / HttpClient 对接 LLM，生态资料多 | C++ + FHttpModule 封装，Blueprint 暴露；也可 |
| 资产生态 | Asset Store 海盗/航海资产极丰富（Synty 等低多边形风格适合独立游戏） | Fab 市场，资产整体偏写实/高模 |
| 个人开发效率 | 脚本驱动、迭代快，中型开放世界友好 | 画面上限高，但 C++ 门槛与构建时间成本高 |
| 推荐理由 | **单人开发 3D 航海开放世界，Unity 6 + Crest 是性价比最优解** | 若追求写实画面+海洋演示效果可考虑 |

> 建议：**Unity 6（6000.x LTS）+ URP + Crest Ocean**，低多边形（Synty 风格）美术管线，把开发预算集中到 Agent 系统与玩法逻辑上——这是"纯 Agent"游戏的核心竞争力所在。

### B.2 AI Agent 集成：2026 主流混合架构

行业共识（Inworld / Convai / NVIDIA ACE 与自建方案均在验证）：**"手写叙事保关键时刻 + 生成式填充环境空间"的混合模式**。纯开放对话容易跑偏、成本不可控；全脚本又浪费 Agent 价值。

推荐自建分层（比接入商业平台更可控、成本更低）：

```
┌─ 表现层：Unity 角色（动画/口型可选）＋ 对话 UI（打字机/语音 TTS 可选）
├─ Agent 调度层：Intent 路由 + Prompt 组装 + 结构化输出解析(JSON) + 动作映射
├─ 推理层：本地小模型（Ollama/llama.cpp + Qwen2.5 系列）做实时对话兜底
│          云端大模型（DeepSeek-R1 / GPT 系 / GLM）做复杂决策与长篇叙事
├─ 记忆层：短期(上下文 6–10 轮) / 会话摘要(SQLite) / 长期语义记忆(embedding 检索)
│          外加"数值记忆"：affinity(好感度) 等数值直接驱动行为，LLM 看不到的部分不给它决定权
└─ 游戏状态层：经济/船员/事件/声望等确定性系统（强逻辑），Agent 只能"提议"，逻辑层"裁决"
```

**关键工程模式（直接可用的实战经验）：**
1. **Persona 约束**：`你是水手长 Garrett… 回复 1–2 句，≤30 词，用"海狼"口吻… 不知道的拒绝并转移话题` —— 约束列表是"能上架 NPC"与"200 字独白怪"的分水岭。
2. **结构化输出驱动状态**：要求 LLM 返回 `{ "speech": "...", "emotion": "angry", "affinity_change": -10, "action": "mutiny_warning" }`，游戏只解析 JSON 更新状态，**不解释自然语言**——幻觉被限制在文案层，不污染逻辑层。
3. **Prompt-to-Action（P2A）**：玩家说"把二副关禁闭"，LLM 映射到已注册动作 + 参数（actor/时长），蓝图/C# 执行物理行为，而非只回一句话。
4. **数值即边界**：好感度 < 阈值时，某些对话分支**根本不进 Prompt**（LLM 无法被"说服"触发它），把不可控性锁死在数值逻辑内。
5. **记忆三件套**：短期上下文 → 每 10 轮压缩为摘要入 SQLite → 长期按相关性检索注入；记忆带重要性加权与时间衰减（斯坦福 Generative Agents 范式）。
6. **作者锚点**：关键主线时刻强制切入手写剧情，AI 只负责外围 ambient 对话与日常事件——保证叙事节奏与卖点时刻不失控。

**成本控制**：本地模型覆盖 80% 高频短对话（零成本、离线可用）；云端模型只处理重大事件与长叙事（每千词约几美分）。Qwen2.5-3B/7B 级别的本地模型在 Ollama 上可流畅跑。打包时可选内置 llama.cpp，玩家离线也能玩（作为卖点："船员是离线可运行的本地 AI"）。

## Part C · 游戏设计：强逻辑 × 重交互

### C.1 概念与一句话卖点

> **《鲸骨航线》（暂定名，可改）**——你是一艘商船/探险船的船长，船上的 5–12 名船员**全部是 AI Agent**：他们有性格、技能、记忆、人际关系、野心与恐惧。你指挥的不是船，是一群"人"。一句话卖点：**"每一名船员都记得你做过什么，并会为此背叛你或追随你。"**

- 类型：单人 3D 航海贸易/冒险模拟（+ 可选局域网多人合作，后置）
- 视角：第三人称，可上甲板自由行走 + 舰桥指挥模式
- 平台：PC（Steam），鼠标键盘为主，手柄可选
- 目标用户：航海模拟、贸易管理、模拟人生类玩家（《盗贼之海》《大航海时代》《Sunless Sea》《Starbound》交集）

### C.2 核心循环（一次航程 = 一个完整故事）

```
港口整备(补员/装货/听传闻) → 出海航行(风/浪/航线/值班) → 事件遭遇(风暴/海盗/海怪/神秘岛/船内纠纷)
→ 现场决策(与船员对话/投票/拍板) → 结果沉淀(货物/声望/船员记忆) → 靠港结算(卖货/修理/犒赏) → 船员关系演化 → 下一航程
```

### C.3 强逻辑系统（确定性、可博弈，共 6 大系统）

1. **贸易经济系统**：港口间供需动态模型（价格 = 基础价 × 供需系数 × 事件扰动）。玩家可研究套利、囤货、操控单港价格。AI 港口经纪人会谈判（LLM 输出底价区间，逻辑层按区间成交，防被"说破价"）。
2. **船员状态机**：每位船员 = 数值模型（技能/士气/忠诚/疲劳/健康/好感度）+ 性格 Traits（贪婪、怯懦、忠诚、嗜酒…）。数值由确定性规则演化，直接决定航行效率、叛变概率、遇敌表现。
3. **事件因果链**：事件有**可预测的触发条件**（如：士气<40 + 连续 3 天恶劣天气 → 酝酿叛变；携现金>X + 路过海盗湾 → 遇袭概率上升），事件细节由 LLM 生成，但"会不会发生、后果多重"由逻辑层裁决——玩家能学会预判和规避。
4. **声望/阵营系统**：各港口与势力（贸易联盟、海盗兄弟会、殖民军、原住民部族）的声望分，解锁折扣、专属任务、通行权。
5. **船只改装系统**：船体/帆/炮/货舱/医疗舱等模块化升级，全部数值化，影响航速、载重、战力、船员舒适度。
6. **天气与海况系统**：确定性风场/洋流 + 概率风暴模型，影响航程规划（顶风 vs 抢风航行）。

### C.4 重交互设计（玩家与 Agent 的高频、有后果的互动）

1. **自由对话**（自由输入/语音转文字）：随时与任何船员交谈；对话影响好感度、士气，泄露情报或埋下隐患。Agent 之间也会互相聊天、结盟、结仇（社交网络演化）。
2. **决策会议**：重大事件（叛变苗头、分赃、航线选择）触发船员会议，各 Agent 依据性格+立场争论（多 Agent 并行推理），玩家拍板；**反对者会消极怠工，甚至当晚策划夺权**——决策后果是长期的。
3. **命令系统（P2A）**：自然语言命令映射为真实游戏动作："升起主帆""把三副关进禁闭室""给全船加餐"——执行与否、执行质量受船员状态与好感影响（命令可能被阳奉阴违）。
4. **AI 生成叙事**：自动生成的航海日志、船员日记（每个船员视角）、港口传闻、事件后续——每次航程都是不同的"小说"。
5. **锚点事件**：作者撰写的主线（神秘海域的失落航线、船上的旧账）穿插其中，保证卖点时刻的演出质量。
6. **后果可视化**：船员关系图（谁恨谁、谁欠谁人情）、记忆回溯（"他在上一航程救过我"）——让 Agent 的记忆变得可读、可管理。

### C.5 系统耦合原则（强逻辑与 Agent 的边界）

- **Agent 是"嘴和脑的提案者"，逻辑层是"手和法的裁决者"**：Agent 输出意图/情绪/对话，数值系统输出结果。禁止 Agent 直接改数值、发钱、开事件。
- 每个 Agent 行为必须有**可追溯原因**（"为什么二副叛变？→ 忠诚 23 < 30 阈值 + 你克扣了他的奖金（上周事件记录）"），游戏内提供"原因面板"，这是"强逻辑"体验的核心。
- 全部关键状态落盘 SQLite，支持存档、回溯、复盘。

## Part D · 开发与上线路线图（单人 9–12 个月）

## Part F · 开发机硬件评估（本机实测 2026-08-07）

**结论：本机远超 Unity 6 推荐配置，作为开发主力机完全达标，无需升级。**

| 组件 | 本机实测 | Unity 6 需求（官方） | 判定 |
|---|---|---|---|
| CPU | **i5-13600KF**，14 核 20 线程，3.5GHz | 最低：双核 SSE2；推荐：8 核+ | 远超。C# 编译、光照烘焙、多 Agent 逻辑运算毫无压力 |
| 内存 | **32GB**（31.8GB 可用） | 最低 8GB / 推荐 16GB | 充足。可同时开 Unity 编辑器 + 浏览器 + Ollama 本地模型推理 |
| GPU | **RTX 4070 Ti 12GB**（WMI 报 4GB 为 Windows 显示溢出，实际 12GB GDDR6X） | 最低 DX10 显卡；URP/HDRP 建议 GTX 1060+ | 远超。Crest 海洋 FFT、水反射、后处理轻松 60fps；CUDA 可加速本地 LLM 推理 |
| 硬盘 | 1.9TB，剩余 654GB | 建议 SSD，20GB+ 可用 | 充足。Unity 安装 + 项目 + 资产包无压力 |
| 系统 | Windows 11 家庭版（24H2） | Win10 21H2+ / Win11 x64 | 兼容 |

**三个注意点：**
1. **本地 LLM 推理吃显存**：qwen2.5:7b（Q4 量化 ≈ 5GB VRAM）可流畅跑，14b（≈ 9–10GB）可尝试但会挤占游戏编辑器显存——建议推理用小模型 3b/7b，编辑器与 Ollama 分时使用；
2. Win11 **家庭版不支持 Hyper-V**：不影响 Unity 开发；若未来需要本地虚拟机联机测试，用云服务器代替即可；
3. 性能目标设定：编辑器内 1080p 30fps+ 可接受，发布目标主流中端显卡 1080p 60fps——本机开发时以"更差的机器也能跑"为标准控制性能预算。

## Part G · 开发方向与需求预设

### G.1 开发方向（做什么 / 不做什么）

- **做**：单机为主的"AI 船员社会模拟 × 航海贸易"；**架构上预留多人扩展**（游戏状态与表现层解耦），多人放在 EA 之后第二版本；
- **不做**：不做写实级船舶流体模拟、不做无缝超大地图、不做 AAA 画面——个人开发者工期与性能双不允许；
- **美术**：低多边形风格（Synty 类），资产商店购买为主，控制成本与性能。

### G.2 需求预设（可量化验收标准）

| 维度 | 预设 |
|---|---|
| 平台 / 帧率 | PC Steam；发布目标中端显卡 1080p 60fps；编辑器内 30fps+ 可接受 |
| 世界规模 | 1 张 8km×8km 海域图（分区加载），15 个港口，程序化生成岛屿变体 |
| 船员规模 | 同屏活跃 Agent 8–12 名（完整模拟）；全船 20–30 名（非活跃降级为轻量状态机） |
| 对话延迟 | 本地模型 <1.5s，云端 <3s，流式输出 |
| Token 预算 | 单航程（≈1 小时）每船员 ≤15k token；本地 80% / 云端 20% |
| 存档 | SQLite 全状态快照，支持断点续玩、回溯 |
| 本地化 | 首发中英双语 |
| 内存预算 | 项目峰值 <16GB（确保 32GB 机器可同时开编辑器+浏览器+Ollama） |
| 包体 | <10GB；离线模型包**不内置**，作为可选 DLC 形式按需下载 |

### G.3 技术栈明细

- Unity 6 LTS（6000.x）+ URP + 新 Input System；游戏内 UI 用 UGUI，编辑器工具用 UI Toolkit；
- 海洋：**Crest Ocean**；浮力：Crest 自带或资产商店浮力插件；
- AI：本地 **Ollama**（qwen2.5:3b/7b）+ 云端 **DeepSeek API**，统一 HTTP 封装层，支持运行时切换与降级（云端挂了回落本地，本地挂了给模板回复）；
- 记忆：SQLite（摘要/事件/好感度）+ 本地 embedding 模型做长期记忆检索（bge-m3 / nomic-embed 类）；
- 多人预留：状态层与表现层解耦 + 事件驱动，为后续权威服务器模式做准备。

## Part H · 线上互动（多人化）所需条件

### H.1 建议形态：合作制，而非竞技制

- 推荐 **1–4 名玩家同船/同舰队的合作模式**：航海节奏慢、天然容忍 200ms 级延迟（远优于射击/竞技），这是航海题材做多人的先天优势；
- 交互设计：只有**船长**对 AI 船员做完整自由对话交互；其他玩家担任高级船员，可下命令但经船长逻辑裁决——把 LLM 交互集中到单点，AI 成本与同步复杂度都可控；
- 多人不是 MVP 的一部分：单机先行，**EA 后第二版本**上线多人，避免单人开发周期失控。

### H.2 技术条件

| 层 | 方案 | 说明 |
|---|---|---|
| 同步框架 | **Mirror**（社区成熟、文档多、自托管）或 **Unity Netcode for GameObjects + Relay + Lobby**（官方全家桶） | 起步推荐 Mirror；后期需要权威服务器时迁移成本低 |
| 连接 | Steam 好友直连 + **Steam Datagram Relay（SDR）**（Valve 免费中继）→ 规模后上专用服务器 | SDR 起步 0 成本 |
| 权威性 | **服务器权威**：船浮力物理、AI 决策、经济结算必须服务器裁决 | 反作弊刚需；客户端只做表现与输入 |
| 专用服务器 | AWS 东京/新加坡等海外机房，按量计费 $20–100/月 | **必须海外**，见合规 |
| Steam 联机层 | Steamworks API：Lobby、好友邀请、Steam Networking Sockets | 复用 Steam 生态 |

### H.3 合规条件（关键风险，务必提前规划）

1. **性质变化**：单机买断 → 监管轻；一旦提供**在线多人服务**，游戏进入"网络游戏运营"范畴，监管要求显著升级（实名认证、防沉迷、内容审核等——个人主体几乎无法满足境内要求）；
2. **策略**：服务器与主要目标用户**全部放在海外**（Steam 国际版 + 海外机房），规避"在中国境内运营网络游戏"的定性——这是当前国产独立游戏多人出海的主流做法，风险可控；**绝不在境内架设服务器/面向境内公众运营**；
3. **隐私政策**：收集昵称、IP、存档数据必须提供隐私政策（Steamworks 上架要求 + GDPR 等），游戏内与商店页均需展示；
4. **UGC 内容安全**：玩家间文字/语音聊天属生成内容，需提供举报/屏蔽/过滤机制，年龄分级问卷按多人 UGC 从严填写；
5. **服务器成本**：起步阶段 SDR 免费；随在线人数增长，专用服务器 $20–100/月，需在定价模型中预留。

### H.4 AI 多人化的特殊成本

- 多个玩家 × 多名 AI 船员 → token 量线性放大：**必须服务端统一调度**，避免每个客户端各调一次；
- 坚持"本地模型为主"：多人模式下每个连接玩家承担自己的本地推理（同船场景由船长端统一推理 + 广播结果），云端调用仍只用于低频高质生成；
- 设计兜底：无本地模型/无网络时，船员降级为模板对话（保证游戏始终可玩）。
