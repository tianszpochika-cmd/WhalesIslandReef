# D2 航行与对话闭环：任务总览

## 目标

D2 只实现一个可反复验证的 M0 闭环：

```text
新游戏 → InitialHarbor/SeaTrial → 人物可走动、船可航行
       → 第三人称视角与昼夜变化
       → 与 1 名老水手对话（本地 Ollama 优先，Mock/模板兜底）
       → AgentReply 校验 → 好感变化影响可见状态 → 存档/读档恢复
       → ESC 暂停、继续、返回主菜单
```

## D2 明确不做

贸易价格、货物经济、炮战、完整天气模拟、多个岛屿、任务树、完整 NPC 社会、联网联机、Steam 集成和 M1 以上内容不属于本阶段。服务端网关只做可测试的接口基础，不得阻塞本地游戏内闭环。

## 当前工程事实

- D1 已由用户验收通过，初始港口场景和暂停/返回主菜单已经存在。
- `game/AgentCore/` 是纯 C# AgentCore；必须保持可独立 `dotnet build`。
- `contracts/agent-reply.schema.json` 已存在，是对话回复的单一事实源。
- `game/Assets/Scripts/Systems/` 是强逻辑层，禁止放 LLM、HttpClient 或网络代码。
- `game/Assets/Scripts/Gameplay/` 放 Unity 输入、相机、场景和 UI 适配。
- 当前没有真正的航行控制器、昼夜系统、游戏内对话 UI 或服务端 `/agent/chat` 控制器。

## 执行规则

1. 先执行同步任务 01，冻结范围、数据所有权、最小接口和验收口径。
2. 再执行同步任务 02，冻结本地运行时类型、测试夹具和 EditMode 测试入口。
3. 任务 03-07 依次使用任务 02 的接口，不得再定义同义类型。
4. 同步任务 08 负责把 03-06 的结果合并进 Unity 运行时；同步任务 09 再接好感与存档；最后任务 10 做完整验收。
5. 每个 Agent 必须读 `AGENTS.md`、`docs/CONTEXT.md`、`docs/DEVELOPMENT_STANDARDS.md` 和本文件，并更新当日 `.workbuddy/memory/YYYY-MM-DD.md`。
6. 每个 Agent 只改自己负责的路径，不要顺手重构无关代码；提交前说明文件、验证命令、已知问题和下一步。

## 交付策略

先保证“本地 Mock 可玩”，再接 Ollama；Ollama 不可用时必须自动退回模板回复，不能让玩家卡死。Crest 如果尚未安装，允许使用低成本海面占位实现，但必须保留可替换的 OceanAdapter 接口，不把插件 API 写死到强逻辑层。
