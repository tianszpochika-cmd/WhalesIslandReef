# D1 提示词包 · 总览与调度（先读这个）

> 用途：把 D1（工程底座 + 控制中台）拆为 6 个可独立执行的提示词，交给新 agent 执行。
> 调度规则：**P0 顺序执行（唯一起点）→ P1A/P1B/P1C 并行 → P2 顺序集成**。

## 执行顺序

| 顺序 | 提示词 | 文件 | 说明 |
|---|---|---|---|
| 1️⃣ 必须最先 | **P0 工程底座** | `01_P0_工程底座.md` | 建立 Unity 工程 + 定义 SaveSystem 接口桩（并行三线的共同地基） |
| 2️⃣ 可并行 | **P1A 主菜单控制中台** | `02_P1A_主菜单控制中台.md` | 调用 SaveSystem 接口（桩） |
| 2️⃣ 可并行 | **P1B 存档系统** | `03_P1B_存档系统.md` | 实现 SaveSystem 真实逻辑 |
| 2️⃣ 可并行 | **P1C 初始环境场景** | `04_P1C_初始环境场景.md` | 独立场景，无接口依赖 |
| 3️⃣ 最后 | **P2 集成验收** | `05_P2_集成验收.md` | 三线合流 + DoD + 打包冒烟 |

## 并行安全说明（为什么可以同时跑）

- **单一写者**：P1A 只写 `Assets/Scripts/Gameplay/UI*` 与 `Scenes/MainMenu.unity`；P1B 只写 `Assets/Scripts/Systems/Save*`；P1C 只写 `Scenes/InitialHarbor.unity` 与 `Prefabs/Placeholder*`——**无文件冲突**。
- **接口契约隔离**：SaveSystem 的签名由 P0 定义成"接口桩"（能编译、返回默认值），P1A 只调用签名，P1B 只实现签名——两边互不等待。
- **场景隔离**：MainMenu 与 InitialHarbor 是两个独立场景文件，各自编辑。
- 如发现必须改对方的文件：**停止并回报，不要越权修改**（由统筹者协调）。

## 统筹检查点（每步完成后由统筹者核对）

| 步骤 | 检查 | 通过标准 |
|---|---|---|
| P0 | 编译通过 | Unity 打开无报错；`dotnet build`（AgentCore）通过；SaveSystem 桩存在 |
| P1A | UI 可交互 | 主菜单四项可点；继续按钮调 HasSave() 不报错 |
| P1B | 数据流正确 | 单测通过：NewGame 落库 → HasSave true → Load 还原 |
| P1C | 场景可看 | 港口场景能加载：船 + 老水手可见 |
| P2 | 全链路 | 新游戏→港口→退出→继续→回港口；exe 冒烟通过 |

## 提交到 git 的规范

每个 agent 完成时：`git add -A && git commit -m "<模块>: <做了什么> (D1-Px)"`。
冲突时后写者先 `git pull --rebase` 再合并，禁止覆盖他人改动。
