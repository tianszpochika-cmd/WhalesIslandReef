# 船舶设计原则与范围

## 1. 文档职责

本文档定义船舶系统的设计方向、数据边界、阶段范围和冲突仲裁。具体船型、功能点和模块分别见同目录专题文档。

## 2. 船是玩家的长期角色

船不是装备栏里的一个数字。玩家要能记住它的来历、旧伤、改装、船员和航线。

一艘船的身份由以下内容共同组成：

- 船名、船型、旗帜和船厂；
- 船体轮廓、帆装、甲板布局和船上功能点；
- 改装历史、损伤记录、修理记录和船员故事；
- 贸易、战斗、逃亡、救援和探索经历；
- 船舶日志和玩家做出的取舍。

## 3. 设计原则

### 3.1 真实主义

- 小船能进浅水，但不能承担远洋风暴；
- 大船货多、炮多，但吃水深、人员多、维护贵；
- 快船不能同时拥有最大货舱和最高耐久；
- 军舰不能用低成本长期经营；
- 改装改变用途，但不能无代价把船变成万能船。

### 3.2 可解释的强逻辑

船速、转向、吃水、载重、损伤、进水、倾斜、火灾、锚泊、船坞价格和改装兼容性均由确定性系统裁决。

玩家必须能知道“为什么变慢、为什么走锚、为什么进不了港、为什么船坞拒绝安装”。

### 3.3 Agent 权限

Agent 可以：

- 将“收帆”“左满舵”“派人堵漏”映射为结构化命令；
- 根据船员人格生成提醒、争论和工作报告；
- 在事实日志已经产生后生成摘要。

Agent 不可以：

- 直接修改船速、耐久、货舱、炮位、吃水或价格；
- 自己决定碰撞、走锚、炮击和沉船结果；
- 通过对白绕过船型兼容、材料、资金、声望或船员条件；
- 直接写船舶状态或存档。

## 4. 船舶数据所有权

| 数据 | 唯一写者 |
|---|---|
| 船型与基础属性 | ShipCatalog |
| 船实例身份和安装模块 | ShipInstanceSystem |
| 航速、转向、吃水和航行状态 | SailingSystem |
| 进水、倾斜、火灾和结构损伤 | ShipStateSystem |
| 锚、锚链、缆绳和泊位 | MooringSystem |
| 改造、改良、拆除和施工 | ShipyardSystem |
| 货舱、重量、体积和货损 | CargoSystem |
| 炮位、装填、命中和战斗损伤 | CombatSystem |
| 船员岗位、轮班和工作效率 | CrewSystem |
| 日志 | LogSystem，只追加事实 |
| 存档 | SaveSystem，只序列化和恢复 |

## 5. 四层结构

1. 纯数据层：船型、船体模板、模块、功能点、材料和标签；
2. 强逻辑层：航行、状态、锚泊、船坞、货舱和战斗；
3. 表现层：模型、帆、船体运动、交互、UI、动画、音效；
4. Agent 层：命令识别、船员建议、报告和日志文案。

依赖方向必须是：表现层 → Agent 层 → 强逻辑层 → 数据层。

## 6. 阶段范围

### D7 之后优先

- 保持 D4 的 5 种船型和 6 个改装槽兼容；
- 先稳定船型、模块、功能点和存档 ID；
- 先完成小渔船、单桅纵帆船、双桅快帆船三个样板；
- 先跑通航行、靠泊、抛锚、起锚、装卸和基础修理。

### M4—M5

- 20 种船型目录；
- 80 个改装模块；
- 60 个船上功能点；
- 船体损伤、进水、倾斜、火灾、断帆和舵损；
- 船坞、材料、工期、旧船折价、势力限制；
- 船与暗礁、浅滩、红树林、风暴、贸易、战斗和生态联动。

### M6 后置

- 多点浮力和复杂船体物理；
- 船体逐段断裂和自由破坏；
- 舱室家具自由摆放；
- 实时修船和装填小游戏；
- 完整独立小艇驾驶；
- 水下船体检修和多人共享船舶。

## 7. 设计完成条件

- 20 种船型各有用途、优势、短板、历史说明和开放条件；
- 80 个模块各有作用、代价、兼容性、等级和外观；
- 60 个功能点有唯一 ID、状态、交互入口和适用船型；
- 维修、改造、改良、装饰互不混淆；
- 旧存档继续可读；
- 所有数值修改都有唯一写者；
- 文档明确区分已实现、设计中和后置内容。
