# 船舶表现、UI、声音与验收

## 1. 模型表现

每种玩家船型至少准备：

- 远景轮廓；
- 中景完整船体；
- 近景甲板；
- 功能点模型；
- 破损、进水、着火、断帆和倾斜表现；
- 改装前后差异；
- 夜间灯光挂点；
- 水下吃水和碰撞轮廓。

船型远景必须通过桅杆数量、帆面、船头、船尾、炮窗、甲板层数、长宽比、吃水和旗帜识别。

## 2. 船舶动画

至少需要：

- 船体随波上下浮动；
- 转向时轻微倾侧；
- 加速和减速时帆具变化；
- 升帆、降帆、收帆、断帆；
- 舵轮和舵柄同步；
- 锚链下放、收起、绷紧和松弛；
- 缆绳系泊和断缆；
- 甲板货物滑动；
- 进水水位；
- 火灾、烟雾、灭火和爆炸前兆。

## 3. 船舶声音

至少区分：

- 木板吱响；
- 帆布绷紧；
- 绳索摩擦；
- 桅杆受力；
- 锚链拖动；
- 锚机转动；
- 舵轮与舵传动；
- 水泵和水桶；
- 船体进水；
- 船底擦礁；
- 货物碰撞；
- 炮声、装填和火药；
- 缆绳张力；
- 风暴中的结构呻吟。

声音可以提示风险，但必须提供视觉、文字、颜色或震动替代。

## 4. 船舶 UI

至少需要：

- 船体耐久、进水、倾斜、火灾和舵损；
- 当前速度、航向、帆面、风向和海深；
- 货舱体积、重量和分布；
- 淡水、粮食、火药、医药和维修材料；
- 船员岗位、轮班、疲劳和缺员；
- 锚、锚链、漂移、泊位和缆绳；
- 模块、功能点、等级、磨损和互斥；
- 船坞订单、材料、工期和资金；
- 船舶历史、日志和损伤原因。

## 5. UI 信息语言

不要只显示“失败”。应显示：

- “水深不足，当前吃水为……”
- “锚链太短，风浪增强后可能走锚”
- “没有木工或备用木材，无法堵漏”
- “货舱体积未超限，但重量已使吃水增加”
- “炮位占用舷侧空间，无法安装医务区”
- “船员疲劳过高，调帆时间延长”

## 6. 性能

- 远景船型使用低面数和低频动画；
- 远景只保留船体、帆面、旗帜和关键轮廓；
- 近景功能点按距离启用交互；
- 船员和甲板物使用对象池；
- 进水、火灾、绳索和泡沫特效限制数量；
- 海面和船体碰撞使用分层精度；
- 50 座岛流式加载不应因为船体资源产生明显卡顿；
- 1080p 目标设备下维持既有航行和 HUD 性能门。

## 7. 设计验收

- 20 种船型有完整目录、用途、优势、短板和历史说明；
- 80 个模块有唯一 ID、等级、收益、代价和兼容关系；
- 60 个功能点有状态、交互入口和船型适用范围；
- 改造、改良、维修和装饰在 UI 中分开；
- 旧存档读取后船舶仍可航行；
- 船舶状态、模块状态和功能点状态能保存恢复；
- 船员岗位能影响航行、装卸、维修和战斗；
- 舵位、锚位、缆桩、炮位、货舱和维修点可被玩家识别；
- 风、浪、天气、吃水和船体运动表现一致；
- Agent 不能直接改变船舶数值。

## 8. 工程 DoD

- 纯逻辑可脱离 Unity 编译测试；
- Systems 无 LLM、HttpClient 或网络代码；
- 跨端字段先走 contracts；
- 无重复的船舶事实源；
- 文档、测试、验收、路线图和当日记忆同步；
- 本目录内专题文档之间的字段、数量和阶段口径一致。
