## 2. 视觉方向冻结

### 2.1 三句总纲

1. **统一风格化低多边形**：几何简洁、轮廓清楚、材质层级少而有意图；不是方块堆叠，也不是照片级写实。
2. **可信比例**：人、船、码头、门窗、货箱和岸线遵循 1675 年加勒比海的可理解尺度；可夸张轮廓，不可破坏交互和航海判断。
3. **清晰光照与反馈**：天气、湿度、风、海况、损伤、可交互点和 UI 状态必须能通过形状、材质、运动、声音和文字多通道表达。

### 2.2 视觉支柱与反例

| 支柱 | 应有表现 | 明确反例 |
|---|---|---|
| 历史可信 | 木、帆、绳、石、泥、金属和织物有可解释的工艺差异 | 现代塑料、霓虹科幻、无法解释的机械细节 |
| 低多边形秩序 | 主轮廓低面数，边缘和色块服务于识别 | 随机方块岛、纯白地面、未处理的默认材质 |
| 海岛层次 | 海水—湿岸—沙地—植被—建筑有清晰过渡 | 海岛被单一颜色切成几何平板 |
| 角色可读 | 服装、姿态、工具和色块表达岗位与身份，比例稳定 | 仅换颜色复制所有人，或模型成为无碰撞的图标 |
| 反馈有因果 | 天气、船损、鱼群、交互和警告同时有视觉与非视觉提示 | 只用颜色、只用 HUD，或用特效掩盖未实现逻辑 |
| 克制而有温度 | 阳光、风、雨、港口烟火和室内暖光形成节奏 | 过曝、满屏粒子、无休止镜头摇晃和 UI 堆叠 |

### 2.3 颜色、材质和灯光示例原则

以下是调色锚点，不是把逻辑数值写进材质。颜色必须和图标、形状、字幕或音频一起表达状态，不能依赖色盲用户区分单一颜色。

| 用途 | 参考色（sRGB） | 材质/灯光原则 |
|---|---|---|
| 深海 | `#1E5661` | 低饱和蓝绿；水面反射随天气变化，不能变成纯色平面 |
| 浅海/浪花 | `#2F8B8D` / `#D7E4D2` | 浅水与泡沫用透明度、法线和运动区分，避免白色地面错觉 |
| 干沙 | `#C8B07A` | 高粗糙度、软阴影、与湿沙有边界渐变 |
| 湿沙/泥 | `#7F715F` | 更暗、更高对比，接触水边有窄过渡带 |
| 木材 | `#795A3C` | 纵向纹理和粗糙度变化；不同年代/用途不靠随机换色 |
| 植被 | `#3E6B48` | 叶、茎、枯萎状态有形状和明度差，风场响应有节奏 |
| 陶瓦/暖墙 | `#8B4E34` | 作为港口暖色锚点，避免现代鲜艳饱和 |
| 交互提示 | `#E2A654` | 配合图标、轮廓和文本；不可作为唯一裁决信号 |
| 警告/危险 | `#D99A2B` / `#B74232` | 警告使用图标、标签、字幕和音效；颜色只作加速识别 |
| 前景文字 | `#F4F0DA` | 有底板或描边，满足长文本、雨天和色盲可读性 |

材质原则：默认使用少量共享材质；湿木、干木、金属、砂石、织物和水体必须能说明表面状态。参考粗糙度范围为干沙 `0.80—1.00`、干木 `0.60—0.85`、湿木 `0.35—0.60`、金属 `0.25—0.65`、水体 `0.05—0.30`，具体值由材质实例和天气系统驱动，不能由 UI 或 Agent 写入。

灯光原则：

- 太阳、天空和环境光保持同一时间段的方向关系；室内使用有来源的暖色补光，不用无来源的全局发光抹平阴影。
- 阴影必须保留人物脚底、船体接触面、码头和建筑入口的空间判断；低档通过阴影距离和分辨率降级，不删除交互碰撞。
- 过曝以亮度直方图和截图复核控制：玩家模式关键文字、船缘、角色脸部和交互锚点不得因曝光丢失。
- 雨、风暴、夜间和低刺激模式降低闪烁与镜头扰动；同一逻辑状态仍必须可通过静态图标、字幕或日志读出。

## 3. 玩家模式与开发调试模式

### 3.1 玩家模式（默认）

玩家模式只显示玩家需要完成行动和理解后果的信息：任务/关系/资源状态、交互提示、字幕、天气影响、导航、警告和可访问性设置。禁止默认显示：

- GameObject 名称、实体 ID、事件哈希、存档键、LOD 标签、碰撞框、Nav/Stream cell、Profiler、FPS、堆栈和系统日志；
- “占位”“候选”“待审核”等开发状态文字（它们在开发调试模式和交接文档中显示，不进入玩家世界）；
- 不响应的按钮。若功能未开放，必须显示明确的 `未开放/不可用原因/替代入口`，不能让死按钮占据主 HUD。

### 3.2 开发调试模式

仅允许在 Editor/Development Build 或明确的开发启动参数下开启。屏幕必须有 `DEBUG / 本地开发` 水印。允许显示实体 ID、资源状态、LOD、碰撞、锚点、流式 cell、帧时间、GC、实体计数、事件尾部和 Save/Restore 检查结果，但：

- 调试层只读，不能改变系统数值、奖励、关系、天气、实体事实或存档；
- Debug overlay 与玩家 HUD 分层，不能借此通过视觉验收；
- 运行/截图证据必须标注 `player_mode` 或 `debug_mode`；玩家镜头不得带调试水印；
- Agent 可以提出表达和行动建议，但不能通过调试层成为实体的写者。

## 4. 1080p 三档画质冻结

### 4.1 通用基线

- 输出分辨率：`1920×1080`、16:9；D18 允许动态分辨率作为明确配置，但验收截图和性能记录必须标出内部比例。
- 推荐验收档：`Medium`；本地目标为平均 `60 FPS`、`1% low ≥45 FPS`，连续 60 秒采集三次取最差值。
- 逻辑频率、事件事实、存档写入和实体 ID 不随画质档改变。降级只改变表现、可见数量和模拟频率；远景事实仍由所属系统保存和恢复。
- 三档都必须在 InitialHarbor 和 Nearshore 两个场景采集；任何档位超限都要记录原因、责任任务和回退，不得删内容掩盖。

| 档位 | 输出/内部比例 | 贴图上限 | 阴影 | LOD bias | 目标 |
|---|---|---|---|---:|---|
| Low | 1920×1080 / 0.85—1.00 | 1K；英雄资产可由责任人豁免 | 1024，短距离 | 0.75 | 平均 60 FPS；1% low ≥50 |
| Medium（推荐） | 1920×1080 / 1.00 | 2K；英雄资产 4K 需证据 | 2048，中距离 | 1.00 | 平均 60 FPS；1% low ≥45 |
| High（本地审美验收） | 1920×1080 / 1.00 | 2K；英雄资产 4K 需逐项证据 | 2048，长距离 | 1.15 | 平均 60 FPS；1% low ≥45 |

### 4.2 可量化预算、场景与超限处理

每一项预算都必须按“限制—测试场景—采集方法—超限处理”执行。`Target` 是本地开发冻结目标，未写 `Measured PASS` 的条目不得被报告为已通过。

| 指标 | Target（单位） | 测试场景/窗口 | 采集方法 | 超限处理 |
|---|---|---|---|---|
| CPU 主线程 | p95 ≤ `12 ms/frame` | InitialHarbor，玩家从出生点走到码头，60s | Unity Profiler Timeline，三次取最差 | 先查脚本/粒子/动画，再按 LOD/对象池降级；不跳过逻辑 |
| GPU 帧时间 | p95 ≤ `15 ms/frame` | InitialHarbor 日间、雨天、夜间各 60s | Frame Debugger/GPU Recorder；记录分辨率和显卡 | 降阴影、透明、后处理、LOD；不能删除碰撞和事件 |
| 帧率 | Medium 平均 ≥ `60 FPS`，1% low ≥ `45 FPS` | InitialHarbor + Nearshore，各三轮 | 帧时间 CSV/Profiler；记录 warm-up 30s 后 60s | 连续三轮不达标则标 `BLOCKED`，开责任修复任务 |
| GC | 稳态 `0 B/frame`；场景切换单次 ≤ `8 MB` | 60s 航行、登岸、返港各一次 | Profiler GC.Alloc/Memory Profiler | 对象池、缓存、分批加载；不得删除存档或事件 |
| 工作集内存 | Medium ≤ `4.0 GiB` | InitialHarbor + Nearshore 往返 10 次 | Task Manager/Memory Profiler，冷启动和峰值各记 | 卸载远景材质/音频、缩小缓存；保持实体事实可恢复 |
| GPU 纹理内存 | Medium ≤ `1.5 GiB` | 港口高密度视角 + 天气变化 | Unity Memory Profiler | 贴图压缩/尺寸下调/共享材质；英雄 4K 需单独豁免 |
| 运行时资源缓存 | ≤ `512 MiB` | 连续进入四个 streaming cell | 缓存目录大小 + 内容哈希 | 删除可重建缓存，不删除 Registry、存档或事件日志 |
| 首次交互时间 | 冷启动到 Main Menu ≤ `12 s`；InitialHarbor 可操作 ≤ `8 s` | SSD、Medium、无编辑器 | 启动脚本时间戳/录屏 | 预热轻量资源、分批加载；不得让占位资源伪装完成 |
| Cell 切换 | p95 ≤ `3 s`；单帧 hitch ≤ `100 ms` | 出生点→市场→码头→海岸 | Streaming 日志 + Profiler marker | 调整 cell 大小/预加载/对象池；状态必须可保存恢复 |
| 同屏实体 | Low/Medium/High ≤ `96/128/160` 个表现实体 | InitialHarbor 市场和码头镜头 | Debug 只读计数器 + 截图标注 | 远景合批/LOD/cull；不删除实体事实 |
| 同屏 Agent/NPC | ≤ `8/12/16` 个 | 市场镜头，含玩家和核心船员 | 角色 Renderer/Animator 计数 | 远景降低动画频率或替换代理，不改变关系/任务状态 |
| 同屏动物 | ≤ `12/24/32` 个 | 海岸与近海镜头 | Ecology 只读计数 + 录屏 | 远景群体代理/采样频率下降；观测事件仍由生态系统记录 |
| 同屏船舶 | ≤ `4/8/12` 艘 | 码头、离港、近海 | Ship presentation 计数 | 远景 LOD/代理/对象池；不改变航行事实 |
| Draw calls | Medium InitialHarbor p95 ≤ `900`；High ≤ `1200` | 码头和市场最复杂视角 | Frame Debugger，记录透明批次 | 合批/共享材质/LOD；不得以白模覆盖正式候选资源 |
| 可见材质实例 | ≤ `80`；透明材质 ≤ `16` | 市场和船上 | Renderer 材质 ID 计数 | 共享实例/贴图图集；保留材质状态反馈 |
| Mesh 顶点/三角形 | InitialHarbor 可见三角形 Medium ≤ `1.2M` | 码头、出生点、返港 | Frame Debugger/导入报告 | LOD、合批、简化远景模型；不降低交互碰撞精度 |
| 音频声音数 | 同时活动 voice ≤ `32`；循环音乐层 ≤ `6` | 晴/雨/风暴、港口/近海 | Audio Profiler + mixer 记录 | 远景卸载/优先级/ducking；关键警告和字幕保留 |
| 关键提示可读性 | 关键文本/价格/警告 `100%` 可见；无遮挡 | 12+ 固定镜头，三档画质 | 1920×1080 截图逐镜头人工清单 | 调整布局/底板/字体回退，不裁剪信息 |
| 保存恢复完整性 | 迁移、流式切换后实体/事件 ID 丢失 `0` | 离港、天气变化、返港、断点恢复 | Save hash + 只读实体/事件对账 | 失败则保留原档并标 `BLOCKED`，禁止视觉层兜底 |

### 4.3 LOD、裁剪与模拟等级

默认静态/建筑/船舶距离带为：`0—12m LOD0`、`12—32m LOD1`、`32—80m LOD2`、`80m+ LOD3/代理/裁剪`。英雄角色和玩家船可将 LOD0 延至 18m，但必须在导入报告说明理由。每个正式表现 Prefab 至少提供 LOD0/LOD1/LOD2 或记录不适用原因；LOD 切换不能改变碰撞、锚点、实体 ID 或事件事实。

| 等级 | 允许的表现变化 | 禁止的变化 |
|---|---|---|
| Near | 完整材质、动画、交互锚点和阴影 | 不得以特效替代真实碰撞 |
| Mid | 简化骨骼/材质、降低动画频率、共享远景材质 | 不得清除任务、关系、生态观察事实 |
| Far | 代理网格、群体动画、低频视觉刷新、音频卸载 | 不得删除事件、存档字段或导致恢复不同 |

流式卸载前必须先保存所属系统的实体事实和事件游标；加载后由唯一写者重建表现。对象池必须清空旧的材质、动画、交互和字幕状态，防止前一个实体的视觉状态泄漏。

## 5. 模型、材质、贴图、动画和 Prefab 技术规范

### 5.1 单位、轴向、比例、Pivot 与命名

- 单位：`1 Unity unit = 1 metre`；Y 轴向上，Z 轴为前方，X 轴为右方。导入时不得靠运行时缩放修正基本比例。
- 比例：人、门、船舱、船舷、码头和工具优先用 `game/Assets/Content` 的逻辑尺寸/锚点做基准；实测偏差目标 ≤ `±1%`，概念化装饰可放宽到 `±3%` 并记录理由。
- Pivot：建筑/静态物放在支撑接地中心；角色在脚底中心；船在龙骨/水线基准中心；可交互物的视觉 Pivot 不替代所属系统的交互锚点。
- 命名：`<domain>_<role>_<name>_<variant>_v##`，小写 snake_case；Prefab、模型、材质、贴图、动画和碰撞文件同一逻辑 ID。占位资源始终使用 `ph_` 前缀，不得把它改名成最终资产假装完成。
- 目录遵循 [架构第 8.1 节](../../../ARCHITECTURE.md) 与 [视觉路线资源目录](../../D18_D24_VISUAL_PLAYABLE_ROADMAP.md)：`Art/Candidates`、`Art/Models`、`Art/Textures`、`Art/Materials`、`Art/Animations`、`Audio`、`UI`、`Prefabs`；源压缩包不进入运行时目录。

### 5.2 几何预算

| 类别 | LOD0 三角形目标 | LOD1/LOD2 目标 | 必检项 |
|---|---:|---:|---|
| 玩家/核心船员 | `8k—25k` | ≤ `50%/20%` | 脚底、手部工具、脸部轮廓、骨骼命名 |
| 普通 NPC | `5k—15k` | ≤ `50%/20%` | 服装轮廓、碰撞胶囊、远景代理 |
| 英雄船 | `25k—60k` | ≤ `50%/20%` | 水线、桅杆、碰撞体、上下船锚点 |
| 远景船 | `8k—30k` | ≤ `50%/20%` | 航向和水线不可跳变 |
| 建筑/港口模块 | `10k—40k` | ≤ `50%/20%` | 门窗、入口、服务点、静态碰撞 |
| 交互道具/家具 | `0.5k—8k` | ≤ `50%/20%` | 手持点、接触面、遮挡检查 |
| 植被/自然簇 | `0.3k—8k` | ≤ `50%/20%` | 风场响应、透明度、采集碰撞 |
| 动物/宠物 | `3k—15k` | ≤ `50%/20%` | 行走/游动轮廓、行为锚点、群体代理 |

超出三角形目标并不自动拒绝，但必须在资源清单写明资产类别、视觉收益、LOD 方案和实测预算；没有理由的超限进入 `Rejected` 或回到 `Candidate`。

### 5.3 材质与贴图

- 默认贴图最大 2K；4K 仅允许英雄船、玩家/核心角色或镜头中持续近景的关键材质，并绑定逐项预算证据。
- Albedo、Normal、Mask/Metallic-Roughness、Emission 按用途拆分；禁止把状态数值烘进无法复原的贴图。湿润、损伤、雨水和风场是可重建的表现层。
- 透明材质要有排序、阴影和过量 overdraw 检查；叶片、帆、泡沫和 UI 半透明不能无限叠加。
- 色盲模式至少保留形状/纹理/图标/文字第二通道；重要警告不可只用红绿差异。

### 5.4 骨骼和动画

- 人形角色使用统一 Humanoid 映射或项目批准的等价骨架；T/A 姿态、骨骼朝向、根节点和命名在导入报告中记录。
- 角色动作分为待机、行走、奔跑、攀登/上下船、岗位、互动、受伤/恢复、情绪表达和低刺激替代；表达动画不可写关系、任务或资源数值。
- 游戏裁决使用系统事件；动画只接收状态快照，不能通过动画事件发奖、改天气、改关系或改存档。
- 默认采样 30 FPS；镜头近景和关键动作可 60 FPS，但必须说明性能成本。循环首尾误差、脚底滑动、船体接触和转身朝向都要在固定镜头中检查。
- 动物动画随确定性行为状态切换；远景可群体代理，观测、迁徙、救助等事实必须由生态/任务系统保存。

### 5.5 碰撞、锚点与 Prefab

- 视觉网格不作为唯一碰撞。静态建筑使用简单碰撞体组合；船体使用独立船体/水线/甲板/上下船/受损区域碰撞；角色使用胶囊和脚底检查。
- 每个可交互物提供稳定的 `InteractionAnchor`、服务/入口/手持/登船锚点；锚点的世界位置和方向必须有运行时探针或编辑器验证。
- Prefab 根节点使用稳定内容 ID；表现脚本只读快照，不在 Prefab 内复制系统裁决。Prefab 不直接引用临时场景对象；场景只负责摆放和区域配置。
- 占位 Prefab 只能在本地开发状态使用，必须保留替换路径、消费者和回退策略。它们不等于视觉验收通过，也不等于 ReleaseApproved。

## 6. 资源状态机与证据门

### 6.1 六种状态

| 状态 | 含义 | 最低证据 | 可进入运行时 |
|---|---|---|---|
| `Candidate` | 找到或制作的候选资源，尚未完成权利/导入核验 | 唯一候选 ID、来源入口、作者/包名、责任任务 | 仅候选目录或明确本地开发开关 |
| `LicenseEvidenceComplete` | 权利证据字段齐全，但尚未确认表现接入 | 官方来源、下载日期、文件名/哈希、许可证原文、商业使用/修改/再分发结论、署名要求、授权证据 | 不得进入正式构建 |
| `ImportVerified` | Unity 导入结构通过 | 轴向、单位、Pivot、材质、骨骼、碰撞、LOD、Prefab 引用、导入无错误 | 仅导入验证场景 |
| `LocalDevelopmentReady` | 可用于 D18—D24 本地开发轨 | 前两项 + 本地 PlayMode/截图/交互/存档回归 + 消费者和回退入口 | 可进入本地开发构建，必须带状态 |
| `ReleaseApproved` | 具备发布候选资格 | 全部证据、性能/平台/敏感内容复核、构建抽样、责任人类审核者姓名/日期/签名或等价审计记录 | 只有人类责任审核者可批准 |
| `Rejected` | 权利、历史、风格、导入、性能或安全不满足 | 拒绝原因、责任任务、替代/回退或重新提交条件 | 不得进入运行时 |

### 6.2 允许转换和审核纪律

推荐路径：`Candidate → LicenseEvidenceComplete → ImportVerified → LocalDevelopmentReady → ReleaseApproved`。任一中间状态都可以因为证据失效、导入错误、敏感内容未审或超预算进入 `Rejected`。修复后必须新建证据版本并回到 `Candidate`，不得原地擦除历史。

- Agent 可以整理来源、哈希、导入日志和测试结果，但不能填写 `ReleaseApproved` 的责任人签名。
- `Pending`、`CANDIDATE_PENDING_REVIEW`、`ApprovedWithWarning` 或没有责任人/日期的记录均不得推导为 `ReleaseApproved`。
- 候选资源和占位资源必须与稳定内容 ID/逻辑消费者分离；替换表现不改变实体 ID、所有权、强逻辑公式和存档。
- `Rejected` 资源不得因删掉登记、改文件名或只换贴图而消失；新的候选必须引用原拒绝记录和修复证据。

## 7. 大体积二进制资源、Git LFS 与本地缓存

当前仓库可执行 `git lfs`，但本任务未确认远程 LFS 的写入权限、配额、带宽和团队恢复流程；因此本次不把源压缩包或大体积候选包加入普通 Git 历史，也不修改 `.gitattributes`。

冻结策略：

1. 官方下载包、未裁剪源文件和预览压缩包进入本机 `artifacts/external_sources/` 或用户级下载缓存，文件哈希、来源、许可证和下载日期进入证据文档；它们不是运行时资源。
2. 远程 LFS 配额和恢复责任**由人类负责人确认后**，才允许将需要版本化的大二进制纳入 LFS；没有确认前只能提交优化后的开发资源、manifest、哈希和小型验证结果。
3. 普通 Git 禁止单个压缩包超过 `50 MiB`，禁止单个任务把未优化源包批量写入历史；单个运行时资源建议 ≤ `100 MiB`，超过必须拆分、压缩或由人类确认 LFS。
4. 单个 D18 任务的仓库增量目标 ≤ `250 MiB`；超限时先报告并拆批，不用删除内容或改变许可证来压缩数字。
5. 本地缓存使用系统用户缓存目录（例如 Windows `%LOCALAPPDATA%/WhalesIslandReef/D18/cache`），按 SHA-256 命名；缓存可删除、可重建，不能作为唯一来源，也不能被运行时当作授权证据。
6. 构建机必须能在无源压缩包时用已批准的运行时文件复现本地包；缓存缺失应给出可理解错误和候选回退，不静默下载，不接入网络或 LLM。
