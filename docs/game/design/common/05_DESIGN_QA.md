# 设计文档验收与 DoD

## 1. 设计完成不是写完标题

一个领域达到第一版设计完成，必须有：

- 领域总览；
- 领域对象和状态；
- 唯一 ID；
- 数据字段；
- 系统边界；
- 玩家流程；
- NPC 或 Agent 边界；
- 失败和恢复；
- 内容数量；
- 表现要求；
- 阶段拆分；
- 测试和验收。

## 2. 设计评审清单

### 方向

- 是否符合六根设计支柱；
- 是否与 1675 年设定冲突；
- 是否把后置内容错误塞进首版；
- 是否产生万能系统或无代价收益。

### 数据

- 是否有唯一写者；
- 是否有唯一 ID；
- 是否能保存和恢复；
- 是否有默认值和版本迁移；
- 是否需要 contracts 变更。

### 玩法

- 玩家是否知道做什么；
- 玩家是否知道为什么；
- 玩家是否能看见代价；
- 失败后是否有替代路线；
- 是否能形成完整循环。

### 内容

- 条目数量是否有目录；
- 模型、动画、音频、UI 是否有来源；
- 历史与敏感内容是否需审查；
- 是否有性能预算。

## 3. 每个设计任务的交接格式

交接必须写：

- 完成了什么；
- 修改了哪些文档；
- 新增了哪些 ID；
- 谁拥有数据；
- 哪些接口或契约受影响；
- 如何验证；
- 当前未完成项；
- 下一步依赖。

## 4. 设计阶段 DoD

- [ ] 文档有明确范围；
- [ ] 文档有数据模型；
- [ ] 文档有唯一写者；
- [ ] 文档有玩家流程；
- [ ] 文档有失败恢复；
- [ ] 文档有阶段和优先级；
- [ ] 文档有验收标准；
- [ ] 文档已登记到索引；
- [ ] 当日 memory 已记录；
- [ ] 未把规划数字写成已开发事实。
