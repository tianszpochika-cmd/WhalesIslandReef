# D15 内容生产冻结

任务：`D15-S01`  
日期：2026-08-11  
状态：**已冻结，允许进入 D15-A01*—D15-A08*；不代表批量目标已经完成**  
前置：`D14-S01` 已通过，D14 允许 D15 开始批量内容生产。

本文件是 D15 批量生产的唯一口径。它冻结内容数量、ID、目录字段、来源/授权、生产阶段、行为字段、质量等级、LOD、抽样和历史审查门槛。它不新增运行时裁决，不改变任何系统的唯一写者，也不把代表样例数量误报为完整版本数量。

## 1. 冻结结论

- D15 批量内容必须先在本文件对应的代表样例门禁中登记，再进入批量目录；不能先生成一批空壳再补字段。
- 当前 `game/Assets/Resources/ContentRegistry/` 基线为 **124 条目、13 个注册前缀**，状态均为代表性 `prototyped`；这只是 D8—D14 纵切片基线，不是 D15 目标完成数。
- D8 注册表继续使用 `schema_version=1`、小写 `snake_case`、文件名等于 `id`、统一引用图和 `tools/content_registry_check.py`。D15 不私自增加前缀或第二套内容主键。
- D15 目录只保存不可变内容定义、授权资源引用、生产清单和实例定义；运行时库存、价格、损伤、健康、关系、奖励、生态量、任务状态、法律结果和存档状态仍由既有 canonical owner 写入。
- 敏感/历史内容未取得来源证据、审查结论、警告和跳过配置前，状态只能是 `Pending`，不得进入正式生产或逻辑可用状态。
- `Systems/` 不接入网络、HTTP 客户端、LLM 或外部生成服务。资产 Agent 只提交目录和资源引用，不能改变强逻辑公式或系统所有权。

### 3.1 注册前缀

以下 13 个前缀是唯一合法内容主键前缀；目录位置、类别和 owner 必须与 `registry.json` 一致。

| 前缀 | 内容范围 | 目录 | canonical owner | D15 使用口径 |

ID 格式冻结为 `<prefix><lower_snake_case>`；ID 永不因显示名、本地化或资源路径变化而复用。新增前缀必须先更新 D8 注册表规范、owner、目录、检查器和测试，不能在批量任务中临时扩展。

### 3.2 统一目录字段

每一条正式内容定义必须保留 D8 的必填字段。D15 批次清单可以增加扩展字段，但不得删除或重命名这些字段。

| 字段组 | 必填字段 | 冻结规则 |
|---|---|---|
| 身份 | `id`, `schema_version`, `name`, `display_name_key`, `category` | `id` 全局唯一且文件名一致；`schema_version=1`；`display_name_key` 以 `content.` 开头 |
| 语义 | `tags`, `description`, `gameplay_role` | `tags` 写分类、生境、行为或审查标签；不写运行时裁决数值；文本不硬编码逻辑事实 |
| 适用范围 | `valid_regions`, `valid_habitats`, `valid_weather` | 只表示内容适用范围，不替代运行时位置、天气和生态状态 |
| 引用 | `dependencies`, `references`, `asset_refs` | 目标必须存在；`asset_refs` 只能引用 `asset_`；所有关键跨域入口必须可沿引用图追溯 |
| 来源 | `source_refs`, `source_note`, `source` | `source.kind`, `source.author`, `source.reference` 必填；历史事实必须有证据文档或审查记录 |
| 授权 | `license` | `status`, `holder`, `reference`, `commercial_use`, `attribution_required`, `modification_allowed` 必填；正式发行必须允许商业使用 |
| 阶段/状态 | `historical_tag`, `phase`, `status` | `historical_tag` 只允许 `historical`/`inferred`/`fictional`；`phase` 登记进入阶段；`status` 使用 `designed`/`cataloged`/`prototyped`/`production`/`verified`/`deprecated` |
| owner/测试 | `owner_system`, `test_id`, `reviewer` | owner 必须与前缀一致；`test_id` 唯一且可定位测试入口；`reviewer` 登记责任任务或审查入口 |

D15 批次清单另外冻结以下统一生产字段：

```text
production_batch       D15-A01*—D15-A08* 之一
representative_sample  通过门禁的代表内容 ID
production_stage       planning | modeled | cataloged | integrated | verified
behavior_profile       逻辑系统可接管的行为/触发配置引用；不是 LLM prompt
asset_state             missing | placeholder | source_ready | integrated | verified
model_ref               模型或占位资源引用；无模型不能标记 verified
material_ref            材质引用或明确的占位状态
collision_ref           碰撞/交互边界引用或明确的无碰撞理由
lod_profile             本文件第 6 节中的冻结档位
test_cases              与 test_id 对应的加载、交互、保存、恢复和 owner 接管测试
historical_review       Pending | Approved | ApprovedWithWarning | Rejected
review_evidence_refs    审查、警告、跳过、史实和授权证据 ID
content_warning_ids     敏感内容警告；没有警告时填空数组而不是省略字段
skip_allowed            true | false
```

`production_stage` 是 D15 生产阶段，`phase` 是路线阶段，`status` 是目录生命周期，三者不可混写。`behavior_profile` 只描述系统接管入口和标签，不放行为公式；最终行为由 `EcologySystem`、`AnimalCareSystem`、`ShipSystem`、`BuildingSystem`、`QuestSystem` 等 owner 裁决。

## 4. 来源、授权和历史审查

### 4.1 来源/授权字段

所有正式条目必须有可追溯来源和商业授权，不以“待补”“网络找到”或 Agent 生成文本作为证据。扩展清单中的授权记录统一为：

```text
authorization_id       稳定授权记录 ID
rights_holder          权利人/项目内部权利主体
license_ref            许可证、合同或内部创作声明引用
source_url_or_path     外部原始链接或仓库内来源路径；无网络依赖的运行时引用
acquired_at            取得/确认日期
commercial_use         是否允许商业发行，必须为 true 才能进入正式发行内容
attribution_required   是否需要署名
modification_allowed   是否允许修改、重拓扑、重混音或再导出
expiry_or_scope        有效期、区域、平台或用途限制
evidence_ref           可审计证据文件/审查记录
```

项目自有内容沿用 `source.kind=project-authored` 和 `license.status=internal-authored`。外部占位资源必须继续指向 `game/Assets/Art/Placeholder/PH_ASSET_SOURCES.md` 与对应许可证文件。授权不完整、商业使用为 false、修改权限不明或来源无法复核的内容只能留在草稿，不得进入 `production`/`verified`。

### 4.2 历史和敏感内容门禁

`historical_tag` 只表达内容性质，不等于审查通过。每条内容还必须有 `historical_review` 和证据引用：

| 状态 | 可见范围 | 批量准入 |
|---|---|---|
| `Pending` | 仅审查工作区 | 禁止正式生产、禁止逻辑接入 |
| `Approved` | 可按正常表现等级使用 | 允许；仍需来源与授权字段 |
| `ApprovedWithWarning` | 必须显示上下文/内容警告，可选择低强度或跳过 | 允许；警告、跳过和表现等级必须完整 |
| `Rejected` | 不进入游戏内容图 | 禁止；保留审计记录，不删除问题以伪造通过 |

以下内容无论是 `historical`、`inferred` 还是 `fictional`，都必须在进入生产前完成审查：殖民制度、奴役/强迫劳动、宗教仪式与冲突、捕鲸/珍稀动物交易、私掠/战争、土地占有、疾病、赌场/牌局、葬礼和现实社群身份。

敏感内容的最低字段为：`content_warning_ids`、`context_note_key`、`skip_allowed`、`presentation_levels`（至少 `Full`、`Contextual`、`LowIntensity`、`Omitted` 中适用的值）、`review_evidence_refs`。未确认警告时不进入逻辑；选择跳过只写“已跳过”事实，不伪造奖励、关系、声望或任务结果。

## 5. 资产质量等级

质量等级是生产验收，不是运行时状态。批量内容必须达到本节规定的最低等级。

| 等级 | 名称 | 必备内容 | 允许范围 |
|---|---|---|---|
| `Q0` | 计划 | ID 草案、owner、来源计划、代表样例引用 | 不进入正式目录，不可被游戏加载 |
| `Q1` | 目录可扫描 | 完整 D8 字段、授权证据、占位/真实资源状态、引用图和测试 ID | 可做目录/读取器验证；不可宣称可玩完成 |
| `Q2` | 游戏可用 | Q1 + 可加载模型/材质或明确占位、碰撞/交互入口、行为接管、保存/恢复测试 | 可进入垂直切片和批量抽样 |
| `Q3` | 表现完成 | Q2 + 目标 LOD、音频/UI/本地化、性能检查、历史/敏感审查和最终授权复核 | 可标记 `verified`，进入发布候选 |

代表样例最低为 `Q2`；A01 岛屿、A04 建筑、A06 船体和 A07 角色/宠物的首个样例应达到 `Q3`，以证明批量不是换名空壳。正式批量内容最低 `Q2`，需要最终发行的条目必须达到 `Q3`。Q1 占位内容的 `asset_state` 必须是 `placeholder`，并在 handoff/QA 中登记替换责任，不能与完成数量混报。

## 6. LOD 与性能预算

以下为每个可见对象/资源包的三角面预算（不含共享骨骼、粒子和统一材质实例）。距离档位固定为：`LOD0` 近景、`LOD1` 中景、`LOD2` 远景、`LOD3` 群落/最远景。没有几何体的音频、本地化和纯数据条目标记 `LOD-N/A`，改用流式/混音/文本预算。

| 内容类 | 最低 LOD | LOD0 / LOD1 / LOD2 / LOD3 上限 | 附加预算 |
|---|---:|---:|---|
| A01 岛屿地貌块/港口主体 | 3 | 50,000 / 20,000 / 6,000 / 2,000 | 以分区流式加载；同屏只启用可见块 |
| A04 功能建筑/船坞主体 | 3 | 24,000 / 8,000 / 2,000 / 600 | 文化变体优先复用骨架；实例不复制网格 |
| A04 建筑变体/小型建筑 | 2 | 12,000 / 4,000 / 1,200 | 交互碰撞与外观碰撞分离 |
| A06 船体 | 3 | 35,000 / 18,000 / 7,000 / 2,000 | 船体分区碰撞必须可读；不因 LOD 删除损伤分区 |
| A06 模块/功能点 | 2 | 8,000 / 3,000 / 1,000 | 功能点以锚点/碰撞/音频/UI 数据为主；不写公式 |
| A02 植物/农作物/果树 | 2 | 6,000 / 2,000 / 600 | 远景使用群落代理；近景才启用采集碰撞 |
| A03 动物/鱼群个体 | 2 | 12,000 / 5,000 / 1,500 | 行为频率和活动对象数量由生态预算控制 |
| A05 道具/装饰/服装 | 2 | 8,000 / 3,000 / 800 | 小道具可用共享材质和对象池 |
| A07 角色/宠物 | 3 | 30,000 / 12,000 / 4,000 / 1,500 | 远景使用动画/群体代理；不改变角色逻辑 |

实际运行预算还必须服从 D9/D16 的场景总预算、流式加载和对象池预算；发生冲突时采用更严格的上限。LOD 是表现预算，不得删除船体损伤分区、交互点、采集入口或保存所需的稳定 ID。

### 7.1 计数口径

- “条目/类型/变体”按稳定内容 ID 计数；同一 ID 换名字、换颜色或换模型不增加数量。
- “实例”必须有独立 `instance_id`、位置和可保存状态；单纯复制 prefab 文件不计入 600—1,200。
- A02 的生长阶段、季节变体和形态变体只有在有独立目录字段、资源状态、行为/采集入口和测试时才计数。
- A03 的个体外观、年龄或性别只在内容定义明确且由逻辑系统接管时计数；鱼群旧标记不能当作 300 条动物。
- A07 的 NPC 组合必须有可追踪外观/文化/职业组合来源，不得用完全相同的模板改名充数。
- A08 的支线模板必须有事实事件、失败/替代路线和 pending 奖励请求入口；只有对白文本不计为任务模板。

## 8. 抽样测试和 D15-S02 接管

每个批次都执行四层检查：

1. **100% 目录检查**：JSON 合法、ID/文件名/前缀/类别/owner 一致，字段完整，引用存在，`test_id` 不重复，来源和授权完整。
2. **100% 审查检查**：历史标签、审查状态、证据、警告、跳过和表现等级完整；`Pending`/`Rejected` 或缺授权条目阻断正式生产。
3. **代表样例 100%**：每个批次的代表样例至少运行一次加载、交互/行为入口、保存和恢复，并验证所属系统接管。
4. **分层随机抽样**：按第 7 节比例抽取，必须覆盖该批次所有子类、生境/行为/阶段/槽位/敏感标签；抽样失败不得通过删除问题内容解决。

D15-S02 还必须对每种内容至少抽样一次，并检查数量、唯一 ID、重复模型、缺材质、缺碰撞、缺 LOD、缺本地化、缺授权、错误生境、错误历史年代、缺测试和孤儿引用。资产问题与逻辑问题分开登记责任任务，不由资产生产任务修改强逻辑。

## 9. 所有权与接入边界

| 动作 | 允许的内容生产责任 | 禁止事项 |
|---|---|---|
| 目录登记 | 新增定义、标签、引用、资源状态、来源、授权、审查和测试入口 | 复制一份库存/经济/关系/生态/任务/奖励状态 |
| 资产接入 | 提供模型、材质、碰撞、锚点、动画、音频、UI 和占位引用 | 改 Combat/Ship/Building/Ecology/Quest/Reward/Finance 公式 |
| 行为字段 | 提供 `behavior_profile`、触发标签和 owner 入口 | 使用 LLM 决定动物行为、任务结果、奖励、战斗或法律结果 |
| 实例清单 | 提供位置/owner 引用/功能入口和保存键的目录投影 | 直接写建筑损伤、库存、所有权、价格、健康或任务状态 |
| 审查 | 登记历史来源、警告、表现等级、跳过和审计记录 | 无来源创建历史细节；把 `fictional` 当作免审查 |
| 发布 | 只有 `Q3 + verified + 授权/审查通过 + D15-S02` 才可进发布候选 | 把 Q1 占位、Pending 审查或缺测试条目标记完成 |

UI 只能读取目录、状态快照和事件；Agent 只能提出表达/线索/意图；最终结果仍由所属系统和 Reward/Legal authority 裁决。内容目录读取器不写运行时状态。

## 10. 变更控制

以下内容冻结后不得由单个批次静默改变：目标数量、13 个前缀、必填字段、owner、历史审查状态枚举、质量等级、LOD 上限、抽样比例、商业授权门槛和唯一 ID 规则。

确需变更时，必须补充设计依据、影响的 A01—A08 批次、迁移/兼容方案、测试和 handoff，并重新运行目录检查器与受影响领域测试。新增前缀必须回到 D8 注册表任务；新增运行时字段必须由所属系统任务负责，不能借 D15 资产批次绕过唯一写者。
