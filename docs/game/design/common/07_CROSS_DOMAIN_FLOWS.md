# 跨领域核心流程

本文件把各个目录中的局部设计串成可开发的完整流程。每条流程都要能映射到事件、状态、数据所有权和验收用例。

## 1. 新游戏与第一次出航

```text
角色创建 → 初始船舶与船员生成 → 初始港口登记
→ 装载货物与补给 → 选择目的地 → 起航
→ 天气/潮汐/海流参与航行裁决 → 船员执行岗位动作
→ 发现岛屿/动物/植被/建筑 → 到港或发生事件
```

关键写者：角色系统写角色状态；船舶系统写船体和航行状态；经济系统写货物和资金；环境系统写天气与水体状态；任务系统只消费事件并生成任务进展。

## 2. 港口交易与船舶维护

```text
进入港口 → 港口安全/法律检查 → 市场报价
→ 买卖货物 → 支付工资与港口费用 → 检查船体损伤
→ 进入船坞 → 维修/改装/补给 → 重新计算重量、吃水和性能
→ 离港
```

必须验收：资金不足、货舱超重、许可证缺失、港口敌对、维修材料不足、改装后读档。

## 3. 风暴与环境灾害

```text
天气预警 → 玩家选择绕行/减帆/寻找锚地
→ 风、浪、能见度和海流改变 → 船员执行应急岗位
→ 船体/帆具/桅杆可能受损 → 进水或失火风险上升
→ 船舶系统裁决损伤 → 角色系统裁决疲劳和士气
→ 到港修复、搁浅救援或沉船后果
```

Agent 可以提出应急建议，不能直接修改天气、损伤或船速。

## 4. 海战与接舷

```text
发现敌船 → 势力关系与识别判定 → 船长选择追击/规避/交涉
→ 航向、风向、炮位和距离计算 → 炮击/机动/损伤
→ 船员伤亡、士气和岗位变化 → 接舷条件满足
→ 近战与俘虏处理 → 战利品、声望、通缉与外交后果
→ 维修、埋葬、审讯或交付俘虏
```

必须保留“撤退”和“投降”路径，避免战斗只能以歼灭结束。

## 5. 船员关系与 Agent 冲突

```text
日常岗位与事件 → 疲劳、工资、食物、信仰和文化差异变化
→ 信任/忠诚/恐惧/怨恨变化 → 对话与行为提议
→ 角色系统根据事实裁决 → 合作、争执、罢工、偷窃或叛乱前兆
→ 玩家调解、奖惩、换岗、放逐或接受后果
```

Agent 的对话必须引用当前记忆和事实快照，并通过 AgentReply 进入逻辑层。

## 6. 岛屿探索与生态采集

```text
登陆点检查 → 地形、植被、水源、洞穴和动物群生成/加载
→ 玩家观察、追踪、采集、狩猎或避让
→ 资源数量、动物压力和植被恢复状态变化
→ 发现遗迹/建筑/任务线索 → 返回港口交易或制作
→ 生态变化影响后续可见性、猎物和贸易价值
```

采集必须有工具、时间、风险和恢复规则，不能只做“点击即获得”。

## 7. 存档与恢复

所有核心流程都必须验证：

- 状态变化发生前存档，读档后不重复结算；
- 状态变化发生后存档，读档后能继续；
- 事件已触发但未完成时，恢复到正确的中间状态；
- 内容版本变化时，旧数据能迁移或明确拒绝加载；
- Agent 记忆只保存允许持久化的摘要和引用，不把不可验证文本当成事实。

## 8. 钓鱼、活鱼舱与市场

```text
观察鱼群/读取潮汐 → 选择渔具 → 捕捞结算
→ 分拣鲜鱼/活鱼 → 烹饪、腌制、出售或装入活鱼舱
→ 船体重量和水舱变化 → 到港后价格与库存变化
→ 过度捕捞影响鱼群恢复、社群关系和后续任务
```

## 9. 岛屿资产与经营

```text
产权调查 → 购买/租赁/共同治理 → 规划地块
→ 建造水井、仓库、农地、渔场或船坞 → 招募/协商劳力
→ 生产、消费、税费、维护和防御 → 贷款/保险/再投资
→ 出售、抵押、违约或扩大治理范围
```

## 10. 关系、牌局与装扮

```text
酒馆/甲板/篝火场景 → 对话、牌局、送礼、承诺或换装
→ 角色根据文化、信任、债务和外观做出反应
→ CrewSystem 裁决关系变化 → 任务/岗位/派系后果
→ 日志记录事实 → 服装和关系随存档恢复
```

## 11. 探索、奖励与特殊武器

```text
传闻/地图/社群情报 → 交叉验证 → 准备工具和船员
→ 进入沉船/洞穴/遗迹 → 处理潮汐、敌对者和法律归属
→ 发现奖励请求 → RewardSystem 裁决唯一物品
→ 装船、维护、使用、损坏、收缴或替代恢复
```
