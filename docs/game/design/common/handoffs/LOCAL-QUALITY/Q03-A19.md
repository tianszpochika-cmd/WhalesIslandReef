## 1. 一句话结论

**卡了数月的 Q03 正式动作门禁打开了。** 15 个 D20 动作 clip 从「自造的根节点变换曲线」全部替换为**真实 Humanoid 骨骼动画**，`humanMotion` 由 `0/15` 变为 `15/15`，`genericRoot` 由 `15` 变为 `0`，动画控制器过渡由图 `0` 变为 `19` 条，并新增 `Swimming` 参数。

## 2. 起因

`Q03-A18` 只读诊断（见 [Q03-A18_FORMAL_ANIMATION_ROOT_CAUSE.md](Q03-A18_FORMAL_ANIMATION_ROOT_CAUSE.md)）确认：

- 玩家角色本体 `Superhero_Female_FullBody.fbx` **内嵌 0 个动画**；
- 现有 15 个 `D20_Player_*.anim` 的 `humanMotion=False`，曲线是 `/localPosition.y`、`/localEulerAnglesRaw.*`，**只位移/倾斜动画根，一根骨头都不驱动**。

这直接解释了用户报告的三个缺陷：动作扭曲（没有骨骼动作）、不能游泳（没有泳姿 clip）、上船像控制瓢（没有握舵动作）。

## 4. 技术方案与理由

`AnimationClip.humanMotion` 是**只读** Unity 属性，无法手工设置。因此 builder 采用**曲线同构派生**：

对 15 个 D20 状态，各自指定一个已准入的 Humanoid 源 clip，把源 clip 的全部曲线绑定（130 条/个）复制进新的 `D20_Player_<State>.anim`。

这样做的两个好处：

1. 派生 clip 自动带上 `humanMotion=True`（因为曲线本身就是重定向后的肌肉空间曲线）；
2. 保留了既有资源契约 —— `Q03FormalAvatarActionResourceContractTests` 与 `D20A02PlayerAnimationTests` 都断言 `AnimatorController` 的 state motion 是带曲线绑定的真实 `AnimationClip`，换成 `AnimatorOverrideController` 会破坏该契约。

## 7. 一个必须协同修复的退化（已修）

`D20A02R02CandidateRuntimeBuilder` 原先执行 `animator.avatar = null`，目的是让**生成式 generic 变换路径 clip** 能被当作字面路径消费。

换成 Humanoid clip 后，这个变通会让 Animator **没有 Avatar 可重定向**，候选路线会静默停止动画。已修复为：候选预制体保留其已审计的有效 Humanoid Avatar，`D20PlayerCandidatePresentationBridge` 通过 `HasGenericPathClip() == false` 自动选择 Humanoid pose adapter。

这个退化是本次改动引入的，**已定位并修复，并补了断言防止回退**。

## 9. 一个值得记录的诊断坑

**症状**：在实例化预制体上做骨骼断言时读到冻结姿态（85 根骨骼 0 位移），而 Animator 报告 `avatar` 有效、`humanScale=1.045`、状态正在播放（`normalizedTime=0.5`）。

**根因**：**Animator 剔除**。默认 `CullUpdateTransforms` 模式下，批处理 Editor 认为实例不可见，跳过骨骼更新。

**解决**：求值前设 `animator.cullingMode = AnimatorCullingMode.AlwaysAnimate` —— 这正是 `D20PlayerCandidatePresentationBridge` 在运行时本来就做的。**这是测试脚手架的缺口，不是产品缺陷，未因此改任何生产代码。**
