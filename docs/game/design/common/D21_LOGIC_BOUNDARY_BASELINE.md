# D21-L01 逻辑边界基线

> 冻结主题：D2 / D4 / D9 / D19 / D20 与 D21 航海、天气、海况、锚泊、船况、补给、存档的导航边界
>
> 冻结日期：2026-09-01（Asia/Shanghai）
>
> 本文只完成 D21-L01 的逻辑边界冻结，不宣称 D21-L02—D21-L32 已实现，不宣称可玩、运行时通过或发行就绪。

## 1. 目的与适用范围

D21 的实现必须以本基线为导航约束：

1. 先通过公开契约和所属系统的命令/结果交互，再进入事实事件、只读投影和存档投影。
2. 每份可变事实只有一个写者。下游系统只能读取快照、提交命令或消费结果，不能直接修改上游对象、字典、私有字段或 Transform。
3. D2/D4/D9/D19/D20 的现有实现、兼容垂直切片和历史运行证据与 D21 新逻辑分开；旧入口可作为适配输入，但不能被包装成 D21 已完成能力。
4. D21 逻辑只接受显式 tick 上下文、稳定种子、契约数据和已裁决结果；不使用 Unity 帧时间、系统时钟、不可控随机、网络或 LLM。
5. 船体模型、水面 Shader、特效、输入绑定、物理/碰撞、驾驶表现、场景和性能属于 Runtime Deferred，不影响本逻辑基线的冻结结果。

本基线覆盖：船身份与船型、船体组件与船况、货物容量、船员需求、航线/航程、天气输入、海况和天气影响、锚泊/系泊、港口出发/返港、补给消耗、航程事件和存档责任。它不新增生产代码或跨端协议实现。

### 3.1 关于旧模型的兼容原则

`Save.Models.ShipState` 当前位于 Save 命名空间，但其源码注释已明确“Ship 系统拥有，Save 只序列化/恢复，不能修改数值”。因此 D21 将它视为旧存档兼容模型：Save 不能借命名空间取得写权，D21 也不能在未完成 L02-L04 适配前直接把其字段当成完整的新 ShipInstance。迁移必须保留旧字段，新增字段使用可审计缺省值，并报告缺失而不是静默覆盖。

## 4. D2 / D4 / D9 / D19 / D20 导航边界

### 4.1 D2：控制语义与时间兼容层

- D2 `SailingSystem` 是现有最小控制模型；D21 可读取 `SailingSnapshot` 或经适配器提交控制意图。
- D2 `Tick(SailingInput, float)` 的 `float` 不能作为 D21 权威航程时间、物理位移或抵达条件。D21 使用显式 `D21TickContext` 语义（世界日、固定步序、存档修订、稳定种子），具体契约由后续任务落地。
- D2 `DayNightSystem.Advance(float)` 不能取代 D9 世界天气/海况事实，也不能让 UI/系统时钟推进 D21 航程。
- D21 不直接访问 D2 私有字段、Unity `Transform`、Rigidbody 或场景对象。

### 4.2 D4：升级、战斗、生态与生存的结果边界

- D4 `D4ShipyardSystem` 保留当前升级槽、等级和修饰符的裁决权。D21 只能提交已校验的升级/维修请求或读取结果，不在 D21 复制一套升级价格/等级写者。
- D4 `D4CombatSystem` 的战斗入口接收船体、火炮、船员等输入并返回战斗结果；D21 船况系统负责把合法的损伤事实应用到 D21 船状态。
- D4 生态、鱼类和 `D4SurvivalSystem` 的健康/疾病事实由各自系统拥有。D21 船员需求和天气影响只提交请求或读取结果，不直接修改生态或船员健康。

### 4.3 D9：环境事实与天气输入

- `EnvironmentSystem.Snapshot` 是只读副本；`SetWeather`、`ApplyWeatherEvent`、`ApplyStormEvent`、`AdvanceWorldDay` 和 `Restore` 是环境事实的公开入口。
- D21-L11 只定义输入校验、来源、稳定事件 ID、时间/修订和 owner；实际环境状态仍由 D9 写入。
- D21-L12/L13 使用 D9 快照计算海况/风险/影响。`D9ShipWeatherReader` 的速度与危险派生可作为读取事实，但 D21 不能改读数或把派生值写回环境。
- D9 的港口整备、购买补给和旧 `Depart` 垂直入口必须经过 D19/D3/Ship/Crew 所属 owner 的明确适配；“调用成功”不等于所有跨域事实已改变。

### 4.4 D19：港口生命周期唯一入口

所有 D21 港口出发/返港命令必须走：

`D21 command -> D19RoutedPortCommand -> D19PortCommandRouter.Route -> D19 result/event -> D21 read model / owner effects`

约束如下：

- 只使用 `D19RoutedPortCommand`、`D19PortCommandResult`、`D19PortReadModel`、公开事件和保存投影；不读取 D19 私有集合或通过反射绕过校验。
- 命令必须携带稳定 `CommandId`、`ShipId`、港口标识、世界日、存档修订和声明；重复命令依赖 D19 幂等结果。
- D19 当前路由器能裁决港口访问、泊位和已登记服务生命周期，但不会替 D21 写船况、货物、补给或船员。D21-L09/L10 必须把跨域变化定义为显式 owner effect/adapter，并按事实顺序提交。
- D19 港口坐标、3D 停靠、登船触发、NPC 导航和碰撞均为 Runtime Deferred。

### 4.5 D20：角色/身份只读投影

- D21 需要船员岗位/身份时，只消费 D20 完成后发布的只读投影或通过 Character/Crew owner 的公开命令。
- D20-L01 的边界冻结不等于 D20-L40 已通过；D21 不提前绑定尚未验收的 D20 类型或方法名。
- 动物、NPC、动画、Prefab、Transform、NavMesh 和表现层不参与 D21 数值裁决。

## 5. D21 逻辑推进与不变量

### 5.1 统一命令流

每个跨域动作遵循以下单向链路：

`命令 -> 引用/权限/前置条件/幂等校验 -> 所属 owner 裁决 -> 事实事件 -> 只读投影 -> save_revision 存档`

失败、拒绝、重复、迁移和中断也必须走可审计结果，不能通过部分修改留下半提交状态。事件至少携带稳定 `event_id`、`schema_version`、`owner`、世界日、`save_revision`、输入摘要、原因和结果摘要；同一 `event_id + save_revision` 重放不得重复消费。

### 5.2 航线与航程

- 航线引用必须来自稳定的 origin/destination/route ID；端点不存在、同点、船禁航、补给不足、船况不足或权限无效时拒绝出航。
- 航程推进以显式固定步为单位，顺序固定为：读取环境与船只快照 -> 计算海况/速度/风险 -> 裁决天气影响 -> 裁决补给消耗 -> 裁决航程事件 -> 更新航程投影 -> 追加事实并提升修订号。
- 航程抵达不能由场景距离、碰撞或玩家输入直接决定；抵达由路线/航程 owner 根据已验证的航程状态裁决。
- 出发和返港分别拥有命令、幂等、拒绝码和补偿语义；中断存档恢复后从最后一个已提交步继续，不能重算已提交事实。

### 5.3 天气、海况和船况

- D9 是环境事实源；D21 海况规则只读 D9 快照、船体/船况、路线和锚泊投影。
- 海况数值必须有范围、单位、稳定 rounding/clamp 规则和可复现种子；视觉波浪的振幅、Shader 参数和浮力不进入裁决。
- 船况损伤必须通过 D21 船况 owner 的原子结果应用；结构、进水、倾斜、火灾、舵/帆/桅等逻辑状态不能由动画或物理碰撞直接写入。
- 严重损坏、无法航行、拖锚、补给耗尽、风暴拒航等结果必须产生明确状态/原因码，并可保存、恢复和重放。

### 5.4 锚泊与系泊

- 锚泊前置条件读取水深、底质、风流海况、船质量/吃水、锚链状态和最小船员条件；规则结果由 D21 锚泊 owner 写入。
- 港内 berth/visit 状态由 D19 写入，船侧 anchored/moored 状态由 D21 写入；两者通过公开命令和结果关联，不能共享可变对象。
- `Deploying -> Stable`、`Stable -> Dragging`、`Dragging -> Recovering/Released` 等逻辑转移需要确定性条件和事件；3D 锚点、绳链可视化、碰撞体和实际漂移属于 Runtime Deferred。

### 5.5 补给与存档

- 补给消耗是 D21 航程 owner 的固定步裁决；购买/装载是港口与库存 owner 的命令。库存数量、航程账本和 UI 显示不得各自成为写者。
- 存档至少保存 schema/version、ship/voyage/route/anchor/condition/provision 的 owner projection、world day、save revision、last event ID、seed/step、幂等记录和迁移信息。
- 存档加载顺序为：解析 -> 版本迁移 -> 各 owner 校验 -> 恢复投影 -> 事件/幂等索引重建 -> 发布只读快照。未知版本、重复事件、跨港口状态、无效泊位、负资源和违反不变量时拒绝恢复并保留原始输入。
- SaveSystem 只序列化/恢复，不代替任何 owner 计算速度、消耗、损伤、天气或路线结果。

## 8. D21-L01 DoD 与边界结论
