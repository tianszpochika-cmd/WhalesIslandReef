# 共享设计规则

## 1. 设计层级

所有游戏内容按五层描述：

1. 世界规则：时间、天气、地理、法律和历史；
2. 系统规则：经济、生态、船舶、角色、事件和战斗；
3. 内容目录：岛屿、建筑、道具、物种、角色和任务；
4. 运行时实例：某座岛上的某棵树、某个 NPC、某艘船；
5. 表现资源：模型、材质、动画、声音、特效和 UI。

上一层决定下一层的边界。表现资源不能反向改变系统规则，LLM 不能反向改变数值。

## 2. 设计支柱优先级

冲突按以下顺序裁决：

1. 真实主义；
2. 沙盒自由；
3. 任务是引导而非束缚；
4. 获取与代价透明；
5. AI 船员社会；
6. 强逻辑可复盘。

如果“好看”与“看得懂”冲突，优先看得懂；如果“随机刺激”与“可复盘”冲突，优先可复盘。

## 3. 内容从 0 到 1 的标准

一个内容条目不能只写名称。最少要完成：

- 唯一 ID；
- 类型和所属目录；
- 白话用途；
- 数据字段；
- 所有权系统；
- 生成或放置规则；
- 玩家交互；
- 失败和恢复；
- 视觉表现；
- 音频表现；
- 来源和授权；
- 阶段；
- 测试入口；
- 验收证据。

## 4. 状态与事件

所有可变化对象都要区分：

- 定义：不会被运行时修改的基础数据；
- 实例：某个具体对象的身份；
- 状态：当前健康、位置、库存、关系或损伤；
- 事件：状态变化的事实记录；
- 提议：Agent、NPC 或玩家提出但尚未裁决的动作。

事件顺序必须是：

输入意图 → 条件检查 → 强逻辑裁决 → 状态写入 → 事实日志 → 表现反馈。

## 5. 失败设计

失败结果分为：

- 轻微失败：时间、效率、耐久或价格损失；
- 局部失败：路线改变、资源减少、关系受损；
- 严重失败：战斗损伤、疾病、逮捕、船员伤亡；
- 终局失败：沉船、角色死亡或任务结局。

除明确标记的不可逆后果外，主线内容不得因为一次隐藏随机而永久不可达。

## 6. 历史与虚构

每个历史相关条目必须标记：

- 史实存在；
- 史实改名；
- 时代合并；
- 游戏虚构；
- 仅作视觉参考。

真实社群、宗教、奴役、殖民和战争不能被写成无背景的装饰、商品或敌人模板。

## 7. 玩家可读性

每个系统必须同时提供：

- 状态：现在发生了什么；
- 原因：为什么发生；
- 选择：玩家可以做什么；
- 代价：这样做会失去什么；
- 结果：成功或失败后怎样恢复。

## 8. 范围分级

| 标记 | 含义 |
|---|---|
| P0 | 没有它，核心闭环无法游玩 |
| P1 | 体现项目特色，必须进入 v1.0 |
| P2 | 丰富内容和重复游玩 |
| M6 | 正式版后复杂扩展 |
| Research | 需要历史、文化、法律或技术审查 |

## 9. 一致性门

任何新增内容都必须通过：

1. 是否符合设计支柱；
2. 是否有唯一 ID；
3. 是否有唯一写者；
4. 是否有明确输入和输出；
5. 是否可保存和恢复；
6. 是否可解释；
7. 是否有性能上限；
8. 是否有历史和授权记录。
