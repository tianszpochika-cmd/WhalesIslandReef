# 玩法统一验收

## 1. 通用验收卡

每个玩法必须填写：

- `gameplay_id`、版本、所属系统和唯一写者；
- 玩家入口和最短可玩路径；
- 输入、资源、时间、天气、地点、角色和势力前置；
- 正常结算、部分成功、失败、取消、中断和恢复；
- 即时反馈、日志、UI、音频和世界变化；
- 奖励、成本、关系、经济、生态、法律和任务后果；
- 存档字段、版本迁移、防重复结算和性能预算。

## 2. 必测跨域场景

1. 钓鱼 → 鱼获处理 → 港口价格 → 船员伙食 → 存档恢复；
2. 稀有动物救助 → 图鉴 → 势力声望 → 后续任务 → 释放记录；
3. 岛屿购置 → 贷款 → 建筑 → 种植 → 工资 → 税费 → 资产出售；
4. 牌局输债 → 船员关系 → 债务催收 → 任务抵债 → 读档；
5. 特殊武器获得 → 装船 → 战斗损坏 → 船坞维修 → 保险理赔；
6. 性别/服装改变 → 港口身份检查 → 船员关系 → 存档恢复；
7. 寻宝假线索 → 错误路线 → 伤病/时间损失 → 替代线索；
8. 捕鲸或过度捕捞 → 生态变化 → 价格/动物迁移 → 社群反应。

## 3. 质量门

- 强逻辑结果可复盘；
- LLM 输出不能改数值；
- UI 能解释价格、风险、失败和奖励；
- 任何玩法退出后不会丢失或重复结算；
- 自动化测试覆盖核心公式，Unity 冒烟覆盖实际交互；
- 本地化不改变数字、ID、法律和关系事实；
- 玩法在低 Agent、断网和缺素材降级状态下仍可继续。
