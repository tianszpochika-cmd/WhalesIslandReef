# 统一设计边界 v3.0

> 本文件定义谁可以提出、谁可以裁决、谁可以写入。任何玩法设计都不能绕过这里。

## 1. 优先级

1. 现实主义和历史/敏感内容边界；
2. 玩家可理解、可预判、可复盘的强逻辑；
3. 数据所有权唯一；
4. 沙盒自由和失败可恢复；
5. Agent 的表达、记忆和社会关系；
6. 表现、性能和批量内容规模。

## 2. 玩家边界

玩家可以移动、航行、对话、命令、交易、战斗、采集、钓鱼、探索、种植、经营资产、牌局、换装和选择关系路线。

玩家不能直接修改：金钱、价格、伤害、船体、天气、动物数量、关系结果、声望、法律、任务完成和奖励。玩家只能通过合法行动触发系统裁决。

## 3. Agent 边界

### 可以做

- 自由对白、情绪、解释、建议、会议发言、牌局气氛、传闻和日志摘要；
- 提出岗位动作、路线建议、关系变化提议和 P2A 意图；
- 根据已提供的角色快照引用记忆，不拥有事实数据库的写权限。

### 永远不能做

- 改价格、钱、奖励、伤害、声望、天气、动物、植物、产权、债务或任务结果；
- 直接触发事件、绕过分支条件、生成不存在的物品或修改存档；
- 用一句对白把关系值从负面直接变成正面；
- 在 Systems 中调用 LLM、HTTP 或网络。

链路固定为：

```text
Agent 提议 → AgentReply Schema → 边界校验 → 所属系统裁决 → 事实事件 → Agent 摘要
```

## 4. 系统唯一写者

| 系统 | 唯一写入内容 | 其他系统只能 |
|---|---|---|
| Core/Progression | 玩家技能、成长和通用身份 | 提出训练或奖励 |
| Character/Crew | 角色状态、特质、关系、记忆引用、外观装扮 | 提出对话、任务和行动 |
| Ship | 船体、航行、舱室、岗位执行、锚泊、损伤 | 提出路线和操作 |
| Inventory/Cargo | 物品、货物、重量、体积、耐久、处理 | 请求消耗或添加 |
| Economy/Market | 钱、价格、库存、税、工资、利润 | 提供交易意图 |
| Finance | 信用、贷款、债务、保险、抵押、破产 | 生成合同和任务建议 |
| Property/Island | 产权、地块、租约、治理、建筑归属 | 提出购买或建设 |
| Building/Shipyard | 建筑、船坞、工期、材料、服务 | 读取资源和需求 |
| Environment | 时间、天气、潮汐、海流、水体、光照 | 提供观测输入 |
| Ecology | 植物、动物、鱼群、生态压力、恢复 | 提出采集或救助 |
| Farming/AnimalCare | 农作物、牧场、宠物照料和产出 | 提供动作请求 |
| Faction/Legal | 声望、势力、战争、法律、许可证、检查 | 生成外交对白 |
| Quest/Event | 任务状态、事件触发和日志事实 | 请求对应系统结算 |
| Reward/Collection | 奖励发放、图鉴、收藏、唯一物品领取 | 接收已裁决结果 |
| UI/Audio | 表现状态、输入焦点、音频混音 | 不写强逻辑 |

## 5. 玩法边界

- 捕鲸必须有许可证、历史审查、生态影响和替代路线；
- 珍稀动物不能只设计成高价货物，必须有观察、救助、释放和法律分支；
- 岛屿经营不能绕过居民和产权；
- 牌局不能通过存档刷钱，塔罗不能产生超自然事实；
- 性别和外观可以改变，但不抹除法律、债务、声望和历史记录；
- 特殊武器不允许无代价全方位升级；
- 受压迫群体和历史制度不能被做成轻松的利润优化按钮。

## 6. 存档和事件边界

每个重要结果必须先生成事实事件，再更新对应状态。任务只保存目标和后果引用，不复制一份自己的金钱/库存/关系。

存档必须支持：中断、失败、恢复、重复触发保护、旧版本迁移和 Agent 记忆摘要重建。

## 7. 冲突仲裁

当需求冲突时：强逻辑胜过文案；现实/历史边界胜过收益；唯一写者胜过便利复制；失败恢复胜过软锁；玩家可读反馈胜过隐藏模拟；性能预算胜过无边界同时模拟。

## 8. 新内容准入

新玩法、新物品、新动物、新建筑、新奖励必须提交：需求 ID、设计文件、数据模型、所有权、资产来源、历史标签、跨域事件、存档字段、测试 ID 和失败恢复。缺一项只能进入创意池，不能进入代码。
