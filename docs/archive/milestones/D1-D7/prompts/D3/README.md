# D3 任务总览：贸易与完整航程可玩环

> 目标：完成“整备→航行→登岛→交易→结算”的最小可玩闭环。
> 依赖：D2 已通过验收；本阶段以 `docs/game/design/D3_SCOPE.md` 为范围事实源。

## 执行顺序

| 编号 | 类型 | 任务 | 依赖 | 状态 |
|---|---|---|---|---|
| D3-01 | 同步 | 范围冻结、契约与测试门 | D2 | 已完成 |
| D3-02 | 同步 | 货物定义、库存和货舱系统 | D3-01 | 已完成 |
| D3-03 | 同步 | 港口、岛屿、天气和航程数据 | D3-01 | 已完成 |
| D3-04 | 异步 | 贸易价格、买卖和市场库存裁决 | D3-02/03 | 已完成 |
| D3-05 | 异步 | 航程日推进、事件和结算 | D3-03 | 已完成 |
| D3-06 | 异步 | 游戏内贸易/库存 UI | D3-02/04 | 已完成 |
| D3-07 | 同步 | Unity 运行时接线和交互 | D3-03/04/05/06 | 已完成 |
| D3-08 | 同步 | 存档、好感和 D2 兼容集成 | D3-04/05/07 | 已完成 |
| D3-09 | 异步 | 服务端契约镜像和开发态网关 | D3-01/04/05 | 已完成 |
| D3-10 | 同步 | 三端构建、Unity 测试、文档和验收 | D3-02~09 | 已完成 |

## 协作提示词

本轮由主 agent 按 01→10 顺序执行完成。若后续拆给其他 agent，必须只修改表中所属模块，并在交接中报告新增 API、测试和未完成项；不得并行改同一文件。跨端契约变化必须先改 `contracts/`，再同步 game/server/web（当前 `web/` 尚未建立实现，因此记录为待接入）。

验收报告：[`D3_ACCEPTANCE_REPORT.md`](../../design/D3_ACCEPTANCE_REPORT.md)。
